# 原图单格宽分段水道放水

主包 `2026.10.29.6` 提供 `projected_water_channel_protocol=1`。这是宿主接口，需要完整重启；引擎版本不变。普通水坑、长竖向水柱和含水方块排水模式保持原约束。

在当前唯一物资控制器内调用普通 `bucket_place`，额外显式指定：

```json
{
  "op": "bucket_place",
  "pos": [761420, 63, 793994],
  "expected_state": "Block{minecraft:air}",
  "expected_hand": "minecraft:water_bucket",
  "support": [761420, 62, 793994],
  "face": "up",
  "expected_support_state": "Block{minecraft:cobblestone}",
  "projected_water_channel": true,
  "placement_key": "当前锁定原投影的完整key",
  "channel_direction": "west",
  "channel_length": 8
}
```

接口只支持原图中的一个源格加西侧七格 `water[level=1..7]`，不猜测其它布局。整个局部范围须为当前可见投影、服务器已加载区块，且无容器。八格地板必须是与原图一致的圆石；北墙必须是原图朝南、下半、直形、未含水圆石楼梯，实际南面碰撞形状完整；南墙必须是原图完整玻璃。两端必须是原图未含水、未打开、未受电的上半云杉活板门，其下浮冰也必须已完成。

开始前八格均须实际为空气。正常使用后只接受原源格为 `level=0`，其余格为尚未传播到的空气或原图相应水位。水道内不得有玩家、其它活体或载具。物品和经验球不能被当作活体；原水桶接口对源格中的实体和瞄准射线仍独立检查，不因本模式取消。

原源格上方的圆石允许临时为空气以检修，其余七格上方原圆石必须保持一致。控制器须保留开采回执、回收物资、在放水前恢复玻璃边界，并在操作后恢复原圆石。不能靠移走玻璃墙通过检查后放水。

放水仍使用普通水桶的一次正常交互、当前连接的源格服务器更新、选中桶槽服务器更新、完整库存守恒及预测清零后的八 tick 确认。材料所有权、生命值、附近敌对生物、权限、实际视线和既有永久使用记录检查不变。不同流体模式互斥。

回执中的 `projected_water_channel=true`、方向和长度描述本次范围；`confirmed=true` 只证明源水和桶。必须另外等待并扫描七格实际水流，确认正确方向、端部活板门未改变、没有外溢，再记录水道完成。未知桶结果保留原身份，不自动重用。

已有唯一物资控制器可复用 `projected_channel_water.place(client, source, placement_key, out)`。它只发送一次原生放水请求，并分别保存源格回执和两个时间递增的完整八格水流扫描。源格已确认而下游尚未完成时会保留两者的区别，不重新用桶。控制器仍负责检修口、材料回收、流动后的墙体与活板门复查以及安全收尾。

## 旁侧单顶板检修

`2026.10.30.1` 新增 `projected_channel_service_ceiling_protocol=1`。可显式传入 `channel_service_ceiling` 为源格正上方，或西侧相邻一格的原圆石顶板；不指定时沿用源格顶板。只允许声明的那一格为空气，其它七格顶板仍须与原图完全一致，两处同时开口继续拒绝。所有地板、玻璃、端部与近敌检查不变。

从南侧玻璃上方靠西两格可通过旁侧顶板开口斜向点击原源格地板，从而保留源格顶板和全部玻璃；旁侧顶板掉落不会直接落在源格里。水不能上升到顶板开口，操作后仍须恢复原顶板并独立核验。控制器不得因未回收普通掉落物而假记物资守恒。

脚本调用为 `place(client, source, key, out, service_ceiling=[source[0]-1, source[1]+1, source[2]])`。显式模式须先核验新能力，回执必须回显同一坐标。缺少、错位回显或未知结果均不允许重复用桶。宿主改动需要完整重启，客户端脚本可单独热更新。
