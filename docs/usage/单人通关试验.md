# 单人通关试验

这是独立的单人训练场：使用同一套 Meteor、Kit 和本地 Clef Flash，在新建的生存世界里尝试收集资源、合成工具和推进游戏。长期目标是击败末影龙。它只操作登记为试验场的当前单人存档；服务器上的地图画和已有存档不属于试验范围。

开始、暂停、继续、取消由 Kit 的单人试验页控制。模型从 Kit 当前提供的可行阶段中选择下一步，参数、动作执行和结果检查由已有原生控制器负责。模型不能自行生成任意代码、命令或坐标。关闭 ChatGPT 不会停止已由 Kit 启动的后台试验；Minecraft 必须保持运行。

游戏内入口：**U → 设置 → 单人通关试验**。进入你新建的普通生存存档后，点“开始打龙目标”；“暂停试验”“继续试验”“停止试验”都在此页。也可以通过 Kit 原生 CLI 调用，创建、打开和控制目标均不需要桌面截图或鼠标自动化：

```bash
python singleplayer_trial_cli.py --game /Applications/.minecraft/versions/26.1.2 start
python singleplayer_trial_cli.py --game /Applications/.minecraft/versions/26.1.2 pause
python singleplayer_trial_cli.py --game /Applications/.minecraft/versions/26.1.2 resume
python singleplayer_trial_cli.py --game /Applications/.minecraft/versions/26.1.2 cancel
```

CLI 在安装后的 `config/twob2tkit/material-worker/` 目录，使用同目录 `runtime-python.txt` 指定的 Python。原生接口严格核对当前存档、会话和控制版本；不通过地图画控制器启动试验。试验期临时关闭 Flight、AutoLog、AutoReconnect 和 AutoRespawn，使用正常步行与一次性的正常复活请求，停止后释放自己借用的设置。

目前先验证已有的生存阶段：观察环境、采集起步原木、制作木工具、采集石材、制作石工具、获取食物、收集庇护材料、建造庇护所、露天铁装备、附近探索和死亡后恢复。下界、烈焰棒、末影珍珠、要塞定位及末地战斗仍需补齐原生能力，缺失时会停在明确的能力缺口，不能把“模型给出方案”当作完成这些步骤。只有实际游戏中的 `minecraft:end/kill_dragon` 进度证据才可验收通关。

## 死亡与停止

死亡是本试验可以接受的失败结果。Kit 记录原生死亡状态或试验死亡计数变化，重生后重新读取环境和背包；不把死亡前的动作参数直接拿来重放。卡住、明确失败和结果未确认也会分别记录。

移动遇到落差拒绝时，只有匹配本轮请求且原生已释放所有移动按键的终态才允许重新观察并换一条路线；旧路线会记入拒绝记录。它不会把部分移动算作到达。挖掘、放置和合成的未确认结果继续停止，不套用此移动规则。

暂停和取消仍有作用。玩家手动接管、换到其他存档或进入服务器时，试验控制器必须停止发出游戏动作。单人试验允许死亡，不代表取消服务器防护或其他世界的安全设置。

## 经验如何留下来

经验存放在实际游戏目录的 `config/twob2tkit/singleplayer-trial/experience/singleplayer-experiences.sqlite3`。这是 Kit 自己的项目经验数据库，不修改 Codex 的记忆，也不训练或修改 Clef Flash 的模型权重。

每次尝试分开保存两类信息：原生前后状态提供观察结果；模型可以选择一条简短的结构化经验提案。模型提案只有 `category`、`lesson` 和 `confidence`，从固定规则中选择，不接受代码、任意命令、任意坐标或自由文本。即使模型自称有把握，也不会成为已验证技能。

可留下的规则包括采集后核对实际背包、合成后核对工具入包、移动后重新观察位置、重生后重新规划，以及卡住或失败后先重新观察。未知放置结果、计时结束、模块声称完成和没有匹配请求的回复都不能形成成功经验。

有实际材料或工具增量等正面结果时，同一规则至少需要三个不同原生请求的观察才提供给下一世界。死亡、明确卡住或明确原生失败可以立即留下重新观察的建议。这些建议仍然是观察总结，不证明失败原因，也不授权执行任何动作。

## 第二个世界如何复用

新世界开始决策前，控制器读取与当前游戏版本、Kit 版本、引擎版本、生存模式、难度和维度相容的经验规则，作为模型的额外参考。它仍须扫描新世界、生成新的可行候选，并检查实际执行结果。

跨世界读取的内容只有固定建议、观察次数和版本上下文。第一世界的坐标、世界路径、`world_session`、请求编号、种子和旧行动参数不会导出，因此不会指向第一世界的树、矿点或死亡位置。版本信息缺失或不相容的记录可以保留在日志里，但不会提供给新世界决策。

第一世界经验不能代替打龙能力或保证第二世界通关。控制器会保留失败和未确认边界，逐步积累可用建议；完成过多少个阶段、是否真的击败末影龙，均以实际游戏证据为准。

## 模型知道哪些 Kit 能力

每轮会提供近期目标、长期打龙目标，以及当前已注册宏能力的用途、前置检查、实际 Kit 原语和完成依据。例如采木使用 `walk_path`、`mine_block`，完成须核对原木入包；合成工具使用正常配方/物品栏接口，完成须核对工具。

清单随现场候选过滤，明确区分“当前可执行”“缺前置条件”“尚无执行接口”。它覆盖此试验已接入的宏能力，没有把所有 Kit 菜单都当作模型可直接调用的工具。下界、烈焰棒、末影珍珠、要塞和龙战目前列为明确缺口。

文字和游戏帧共享受限上下文。自动图片模式若完整能力说明超过预算，会明确记录并采用完整结构化文字；强制图片模式超限时等待，不默默截断事实。能力注册表为 `singleplayer_trial_capabilities.py`。

## 控制器热更新

策略、能力说明、经验规则和 Python 宏流程可在当前世界内热更新：验证新源码包 → 精确暂停并确认输入释放 → 保存检查点、核对未决操作 → 替换并备份 worker → 重启后台 worker → 原生重新核对本存档。

```bash
python singleplayer_trial_hot_update.py \
  --game /Applications/.minecraft/versions/26.1.2 \
  --bundle /absolute/path/material-worker.zip \
  --python '/Users/sam/Library/Application Support/MinecraftDecisions/venv/bin/python'
```

此命令从 Kit 项目的 `decision-runtime` 目录运行，游戏和 JVM 不退出。经验库和尝试日志不被替换；同一存档的工作台/庇护地点恢复前会小范围原生核验，背包与完成状态重新读取。第二世界不会恢复这些坐标。

存在未确认的挖掘、放置或合成时，更新保留记录并拒绝自动继续。新增原生宿主接口或界面仍需要对应宿主支持；该入口不声称能任意替换未实现的 Java 接口。

## 开发接口与验证

经验模块是 `decision-runtime/singleplayer_experience.py`，本身不连接游戏、不写动作邮箱、不自动重试，也不提升已有技能等级。

```python
from singleplayer_experience import TrialExperienceStore

with TrialExperienceStore(kit_owned_experience_dir) as store:
    result = store.record_attempt(
        trial_id, action, native_before, native_after,
        receipt=matched_native_receipt,
        proposal=model_fixed_lesson_proposal,
    )
    advisory_rules = store.reusable_rules(current_native_snapshot)
```

原生快照须包含 `server="singleplayer"`、当前绝对 `world_id`、`world_session`、递增毫秒时间、生命、背包和版本上下文。两个快照必须来自同一当前存档；原生回复须有 `native=true`、相同的 `id`/`request_id` 和同一世界的终态。模型可通过 `proposal_question()` 获得只包含固定经验规则的 SystemOne 选择题。

回归测试覆盖模型自称成功、等待超时、重复回复、世界切换、版本不相容、实际物料/工具增量、死亡、卡住、失败、跨世界隐私、任意代码拒绝和数据库写锁。逻辑测试通过不等于已在实机击败末影龙；实机试验的每个阶段仍需另行验收。
