# 只开 Minecraft 的调用方式

当前入口是 HMCL 的 **26.1.2** 实例，已实机加载 Kit **2026.10.7.2**。
实际游戏目录是 `/Applications/.minecraft/versions/26.1.2`，使用 HMCL 的版本隔离。

进入服务器后，按 **U → 生产**：

- **自动砍树**：原生砍伐、拾取和补种。
- **材料任务**：选择物品及背包目标数量，点击“开始获取材料”。
- **投影建造**：使用已经加载并正确放置的 Litematica 投影。
- 投影材料模式提供“自动补齐并建造”；它仍依赖已登记的真实物资来源与实际支持的采集能力，不能保证任意材料都能自动获得。

这些入口不需要打开 ChatGPT 或 Ollama 桌面界面。原生游戏功能直接在 Minecraft
内执行；材料流水线可能由 Kit 启动一个轻量的后台 Python 工作进程，不需要
另开终端窗口。缺少来源或能力时会报告具体缺口。

## 游戏内调用本地模型

按 **U → 设置 → 本地决策模型**，或从“材料任务”页面进入：

- 启用本地决策：Kit 自动启动后台服务，不需要打开 ChatGPT、Ollama 窗口或终端。
- 模型：Clef Flash 接收结构化状态和可选图片；Nimble 使用结构化状态。
- 持续驻留：开启后保持所选模型常驻，每次任务复用；退出游戏或关闭本地决策后释放。
- 上下文：默认 4096，可以选 2048/8192；过长请求会明确拒绝，并沿用本地规则。
- 游戏画面：默认“自动”，控制器要求视觉判断时由 Kit 截取游戏帧；也可以关闭或每次阶段决策都提供。
- 测试当前游戏画面：关闭 Kit 页面，截取一帧并分类；测试不会移动或放置方块。

启用本地模型后，投影材料流水线可在完整审计产生多个可选材料批次时调用它。
单物品配方、数量计算、移动与施工步骤仍使用已有的本地流程。截图来自 Minecraft
的游戏帧缓冲，最大 640×360，不截取桌面；聊天、告示牌及图片文字只作为观察。

模型收到短目标、经过核对的场景事实和有限候选项，返回候选 ID、概率和置信度。
Kit 在返回后再次核对世界、控制权、背包与安全状态，决定是否执行现有动作。
手动接管、战斗、低血量、未确认动作和数量异常会由 Kit 处理。超时、低置信度或
服务未就绪时使用原有规则，模型不会生成游戏命令或宣布工程完成。

本次已验证原生截图、Clef Flash 图片分类，以及“模型选择樱花木板 → Kit 切换
快捷栏 → 实机核实物品守恒”的闭环。阶段测试覆盖 8 类、32 个固定样例；这不
代表能处理所有 Minecraft 场景，也不证明地图画已完成。

## 内存设置

这台机器为 18 GiB 内存。已将当前实例的 Java 堆上限设为 **3072 MiB**；保留
用户设置的 **60 FPS、模拟距离 5、渲染距离 5**。堆上限不等于游戏进程的总内存，
原生资源和图形内存仍会占用额外空间。

Clef Flash 在 4096 上下文下预热报告的模型分配约 **9.75 GB**，图片调用后实测
升到约 **10.83 GB**；之前默认上下文测试约 13.07 GB。相同上下文下，Nimble
约 **8.73 GB**。模型权重仍然很大，同时开游戏与其它程序时可能出现交换内存。
Kit 同时只维持一个所选模型，使用已下载权重创建小上下文别名，不重复下载。
后续日常使用只开 Minecraft 即可；持续驻留意味着模型仍作为后台进程占用内存。

当前相同提示词的 32 个固定阶段样例，两者均 32/32；耗时中位数 Nimble 约
2.0 秒，Clef Flash 约 2.3 秒。需要游戏画面时选择 Clef Flash；只使用结构化
状态并希望少占一点内存时可以选择 Nimble。这组样例不能代表所有游戏任务。
