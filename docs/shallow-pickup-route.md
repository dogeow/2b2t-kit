# 施工浅水拾取与返回

可复用入口：现有 `MaterialClient.collect_shallow`，底层实现位于 `decision-runtime/material_jobs/shallow_pickup.py`。
使用现有材料控制器和原生普通飞行，不重启游戏、不挖方块、不放置方块。

调用前应先清出检修口和低处通道，保留干燥返回列。函数自行读取完整、同一世界/控制版本、预测清零的局部扫描；落脚支撑只能是普通泥土、石头或圆石，上方通道只能为空气或普通水。偏离格子中心、缺少支撑、岩浆、顶棚及不完整扫描均会拒绝移动。

需要唯一材料租约、防护、飞行、自动离线保护、呼吸III、至少19生命和285氧气。最多等待拾取4秒，之后无论拾取是否成功，都先通过同一列返回已验证的干燥位置；人工接管时不发送返回动作。普通导航有高度容差，结果以实际位置、氧气和背包增量核验。

示例使用抽象坐标，不能直接当作实际游戏坐标：

```python
result = client.collect_shallow(
    support=[0, 60, 0],
    item="minecraft:dirt", target_total=6,
    out=proof_directory, return_y=64.3,
)
```

`support` 是扫描确认的落脚支撑方块；`target_total` 是目标背包总数，不能填本次新增数量。调用者应在进入前完成地形开采并核验原生回执，再在返回后继续投影施工。超时只重新观察原掉落物，不能重放原挖掘。流水来源和其它工程物资由调用方另行核验。

动作流程已在两列施工中实际验证，六块泥土全部回收。新的 `collect_shallow` 入口目前通过了离线回归，覆盖超时返回、低氧拒绝、人工接管和空格稀疏扫描；下一次实机复用仍需保存该入口自身的独立凭证。
