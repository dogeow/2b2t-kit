## 1. 执行摘要

该提交将 **2b2t-kit 从 Minecraft 26.1.2 端口到 26.2**（Fabric Loader 0.19.5、Fabric API 0.161.0、Mod 版本 **2026.10.14.4**、运行时引擎 **1.8.0**），并在同一变更集中交付 **大规模地图画（flat projection）效率优化**、**可再生资源采集管线**（树、花、仙人掌、泥转化等）、**控制面可靠性**（背包暂停、取消后只读扫描收尾、悬停采矿目标消失、熔炉熄灭竞态）以及 **生物群系/种子离线校准 CLI**。

文档 `docs/changes/2026-10-14-minecraft-26.2-upgrade.md` 记载：**1978** 项 JUnit、**653** 项变更 Python 模块测试均为 0 失败；实机已在 simpcraft.com 26.2 实例验收连接、Litematica 层边界 API、ProfessionalPrinter 铺图与独立服务器审计。

**总体评价：** 功能与测试覆盖面强，性能改进有离线基准与实机间隔对比支撑；主要风险来自 **单提交体量过大**（难以二分回归）、**元数据/描述未完全同步 26.2**、以及变更文档中 **已承认的 5 项生命周期测试与 `native_inflight` 保留语义不一致**。

## 3. 性能分析

### 3.1 高置信度优化

1. **投影 flat 规划缓存与小区增量** — 数量级离线加速；实机窗口间隔有 before/after JSON（`map-planning-efficiency-20261013-289`）。
2. **重复选材跳过** — 降低原生 snapshot/选材往返。
3. **经验库索引** — 大表统计从秒级到微秒级（仅影响依赖该统计的路径）。
4. **导航停滞检测** — `FlightWatch` 在 `material_client.request()` 导航路径上 10s 无位移触发 `pause_stalled`，避免无限占用心跳与租约（与 guard/interface pause 信用并存）。

### 3.2 成本与权衡

- **悬停/洞顶采集：** 多次 `_scan`、实体稳定等待（0.15s 轮询）、拾取最多 3 次尝试 — **正确性优先**，块数上限 `max_blocks=8` 等有界。
- **可再生行程：** 新模块多依赖 `checkpoint()` 与全状态 `status()` — 长距离巡航时 Python 轮询频率仍可能成为尾延迟来源（未见本提交内统一降频重构）。
- **测试夹具：** `forest-canopy-current.txt` 为约 33 KiB 固定场景；未提供 CI/clone 测量，不能据此判断有显著成本。

### 3.3 26.2 运行时环境

升级文档明确：**Voxy** 在 Apple M3 OpenGL 4.1 上不可渲染、**AppleSkin** 无 Cloth Config UI、**JEI/JER** 部分为 beta/alpha — 不记为 Kit 缺陷，但影响玩家侧体验与依赖 Mod 稳定性。

## 8. 结论与建议

### 8.1 结论

`394949ae` 是一次 **高价值、高风险集中度** 的发布型提交：26.2 端口完整，地图画路径有 **可测量的规划与选材性能提升**，控制面与实机地图审计链条在文档中闭环较紧。缺陷修复针对 **真实线上事故**（背包暂停、扫描取消、目标消失、熔炉熄灭、连接竞态）。主要技术债为 **提交粒度、后端接线文件体量、已知生命周期测试语义漂移、元数据描述滞后**。

### 8.2 建议（不要求在本提交内改代码）

1. **已修正：** 将 5 项 Python 生命周期测试与已发布请求保留策略对齐，保持失败/超时/离线场景覆盖，不禁用测试。
2. **已修正源码：** `fabric.mod.json` 的 `description` 为 26.2；重新构建已通过，正在运行的主包没有为此重启替换。
3. 固定树冠夹具仅约 33 KiB，现有数据不足以要求生成式压缩。
4. 后续功能尽量 **按域拆分提交**（26.2 端口 / 地图画 perf / 可再生管线），便于 bisect。
5. 发布检查单：mods 矩阵 + **twob2tkit-2026.10.14.4** + **engine 1.8.0** SHA + decision-runtime worker 哈希与 `work/upgrade-26.2-642/` 记录一致。
