# 材料任务与投影自动补料

此前，取料、采集、制作和投影续建由不同脚本衔接，需要 AI 逐段安排。Kit 1.9.104 新增原生任务入口，由本地材料后台按当前背包、游戏配方和实际投影差异推进。

## 使用入口

- **生产 → 材料任务**：选物品和背包目标数量。已有物品计入目标，不是额外再收这么多。
- **生产 → 投影建造 → 自动补齐材料并建造**：使用当前选定、锁定的投影，缺料时转取料／生产，再继续施工。

任务显示在顶部 HUD，可暂停、继续和取消。常规流程不调用模型；世界切换、手动接管、低血量锁和不明确的物品操作不会被自动忽略。

## 组成与范围

`decision-runtime/material_jobs/` 分离协议、规划、采集、资源搜索、工位加工、导航与装备管理；`material_jobs_backend.py` 复用现有原生接口和经过实际验证的库存操作。工作台及普通熔炉配方来自当前客户端 JAR，支持十六色混凝土固化。直接采集覆盖当前已有的沙砾、干燥沙地、原木、常见天然岩石、铁铜原矿和煤等适配。

箱子和工位按服务器／维度登记，资源搜索记录持久化。临时潜影盒和寄存工具有独立账本；未确认回收不会被当作完成。背包不足时只自动寄存本任务新增的普通矿物副产物，保护原有装备、食物和当前配方材料。

普通材料后台可以在任务结束后单独更新。新增菜单或原生接口仍需完整重启主包。部署脚本备份旧版、核对文件，记录实际 Python 路径；不依赖 HMCL 改写后的 Java `user.home`。

## 本机实测

从 Kit 页面启动白色混凝土任务：已有 16 个成品，目标 32 个。后台自动查库、补采缺少的沙子、返回工作台制作染料和粉末、进入已有工位固化，最终背包核验 **32/32**；本轮新增 16 个，耗时约 **239 秒**，材料后台模型调用 **0 次**。期间无需人工衔接步骤，结束时生命 20、饥饿 20，封口方块已回收，保留高空 PvE 防护。

该实测发现并修复了界面关闭后的旧快照、远程工作台路线超出步行范围、临时封口缺料、飞行到达后惯性和箱子／半砖脚下碰撞误判等问题，均纳入回归。

投影模式已自动取出并放置 68 个深板岩瓦，完整核验从 **2579/3407** 提高到 **2647/3407**，随后按剩余缺口自动返回补料并进入原料搜索。**整艘星舰从零采集到完工尚未完成整轮验收**，不能把入口可运行或材料测试通过说成整艘已建成。

本次原生构建检查 **1094 项 Java 测试通过**；最新离线材料回归 **411 项通过**。这些测试覆盖协议、规划、库存守恒与异常收尾，不替代所有材料和地形的实机验证。

资源搜索另外验证了保存的真实扫描回执：目标石材存在，但水和重力方块使入口不安全。搜索按小批持续推进，优先已授权旧矿区，记录具体跳过原因；当前搜索算法允许复查旧版本误判的空区，并保存旧记录。

尚无采集适配的原料、特殊配方或不可达工位会明确停止并说明原因。该版本不承诺在任意服务器、地形和物品组合下无需配置即可完成任务。
