# 正常关箱后的地面停靠与待核验观察

定点仓库取煤实机确认 135 块现存煤，正常取入一组 64 块。关箱会清除之前步行和空闲读取的停靠依据，这是为了防止背包交互之后沿用旧的库存证明。但普通 `MaterialClient.finish()` 没有建立新的只读依据，便返回地面收尾待核验。单次取料进程随后结束，心跳到期让满血角色退出。

现在，只在当前世界和控制会话、当前修订下**明确完成关箱**，角色满血、已落地、无移动和其它作业、界面关闭、背包与安全字段完整、无未知原生请求，且实际位置仍与关箱终态相符时，才通过正常 `snapshot` 请求建立新的依据。依据仍由既有 `idle_read_proof` 检查原生请求前、回执、发布后三帧，不能合成步行证明、改写旧回执或推定高空到达。后续仍实际扫描身体柱、检查实体，再执行正常上升和原生停靠。

若地面依据确实无法核验，健康的原材料控制器保持实际状态观察并续约，而不是返回后让进程结束。这个等待不重放原移动、扫描、背包或关箱动作；手动接管、世界或控制权变化时让出。缺失控制权证据不能续约，真实健康保护仍由原生优先处理。
