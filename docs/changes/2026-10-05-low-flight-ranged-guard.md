# 低空防护的远程分类与遮挡升空

引擎 `1.7.81`，宿主 `2026.10.5.1`／API 3 不变。只修改已有防护引擎，可通过正常引擎热载更新；不修改健康锁或复写未决请求。

源码确认两个缺口：远程优先级、升空与近威胁判定遗漏当前手持三叉戟，而普通溺尸分支已经排除这类武器；已有交战对象因遮挡、距离或攻击预算暂不可攻击时，`next == null` 先释放升空再等待，导致角色留在低处。

实测日志记录了同一未决敌人和四次受击，最终触发原生健康撤离。该溺尸在一个真实帧中距离约 11.008、低约 4.764 格，但原帧没有手持物、直接投射物或完整敌人 AABB，不能认定该次一定由三叉戟造成。带附魔的弓、剑和箭数量不变也不能倒推“未攻击”；只能区分已有受击证据与缺少实际放箭、伤敌或击杀记录。

当前活着的 Living Enemy 使用统一远程分类：已知远程类型或真实手持弓／弩／三叉戟；还可接纳同 level、同当前实体引用、准确 source owner、最后攻击者与 0..100 tick 的 typed `DamageTypes.TRIDENT` 事实。不会把所有未武装溺尸归为远程，也不以旧引用提供位置。

独立飞行防护遇到当前已交战、12 格内远程或不可攻击／被挡对象时，先尝试同一次交战固定 `startY + 12`、最多 200 tick 的安全升空。每步复验真实整段身体、干燥危险方块、真实服务器区块和现身敌人；不能向上靠近头顶敌人或穿过其身体。仅借用已有 Flight 设置和正常输入，不瞬移、垫方块、追进水中或对无 LOS 对象发攻击。未知、墙顶或 Flight 冲突走原地防御 fallback；原 `<14` EmergencyExit、健康锁和恢复授权边界不变。

整段柱证明还要求实际位置、速度和身体／敌人 AABB 的所有坐标有限、身体尺寸有效。已确认整柱安全后先关闭旧遮挡 peek 的 Flight 租约，再借用升空租约。头顶敌人的限制只作用于其实际 AABB 与整段身体在原危险半径内的情况（苦力怕 6／高压 12，其他近威胁 9／远程 12）；远在侧面或整段柱上方、始终未进入该半径的现身敌人不作为假屋顶。任何穿体、近上方或未知 AABB 仍拒绝升空。

升空不清除 unresolved UUID，也不记击杀；后续施工恢复继续依赖原 safe-separation 严格门。新增日志记录实际当前位置／AABB、手持物、伤害来源、可攻击原因及固定目标，仅状态变化或节流时写入。未观察的数据明确为 unknown，不从调用 `raiseShield` 推断有效盾防。

当前修复仍须完成受控实际验证；编译和纯策略／接线测试不代表不再受伤或无人值守完成地图画。

新增 16 项策略及 ASM 接线回归覆盖武器分类、同攻击者事实、不可攻击时的固定升空、有限 AABB、远近上方敌人和 Flight 租约先后；原区域挖矿接线检查保留四键及真实鼠标／键盘 API，并检查其委托关系。针对性 60 项检查和完整 `test jar verifyRuntimeEngineJar --offline` 均通过，Java 总计 1746 项，无失败、错误或跳过。待安装的独立引擎 SHA256 为 `16b9da95ddd817ecaf8e19897e4d98522f5e04da650d38ab915ccdf5cde28dfb`；当前已安装主包仍为原 `2026.10.5.1`，不能把重新构建的同名主包当已安装版本。
