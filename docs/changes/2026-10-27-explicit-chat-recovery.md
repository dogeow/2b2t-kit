# 明确人工聊天恢复确认

用户可在安全恢复后直接在AI聊天中确认接管，不再强制自行点击游戏里的“我已回来”。原按钮仍保留。聊天确认由操作端明确提交，游戏不读取公共聊天，也不把目标自动续跑、旧许可或模型生成的文字当成人工确认。

主包27.4提供confirm_recovery，快照能力explicit_recovery_confirmation_protocol=1。调用方必须保存本次直接人工指令的引用、原文和记录时间，绑定confirmed_hold_time。该许可只针对一个事故；同一事故的许可可跨普通操作继续使用，不能覆盖后来的事故。请求本身仍绑定当前世界、控制版本及12秒有效期。

原生重复核验当前玩家存活、生命至少18、食物至少8、事故服务器/已记录维度与玩家一致、控制空闲、至少5秒无新伤害。只允许无界面、暂停菜单或安全空背包；鼠标携带物品、合成格内容、其它容器和聊天草稿均保留。确认成功后先武装PvE，再关闭安全界面，控制版本增加1。

确认写入来源explicit_chat，保留真实人工引用，不伪造game_ui。Python入口recovery_confirmation.confirm只发送原生请求，不编辑安全文件、不重连、不自动重试；未知回执保留。安全锁读取同时验证原生确认元数据，新的事故仍阻止自动控制。现有未知挖掘/放置请求不受确认影响，也不得重放。

生命保护离线后，自动goal续跑不能自行重连。用户直接确认本次恢复时，27.6提供独立的恢复连接路径：connect_server携带recovery_only=true、同一事故的真实人工确认及当前标题页范围，目标必须在已保存服务器中且与事故服务器一致。原生以事故和人工引用为键，用CREATE_NEW预留一次连接机会；失败或未知结果不会自动重试。连接期间安全锁仍有效，进入世界后重新核验健康、维度和玩家，再单独confirm_recovery。Python的connect_once不会清锁，普通connect入口仍拒绝健康锁。

恢复命令有自己的严格空闲检查，不能先进入会拒绝健康锁的普通闲置任务交接。首次启动标题页也有独立随机会话范围，避免空标识令恢复请求失效。27.4/27.5实机拒绝均发生在实际服务器连接和一次性预留前，原始错误回执保留；上述两处修复分别有分发及启动生命周期回归。
