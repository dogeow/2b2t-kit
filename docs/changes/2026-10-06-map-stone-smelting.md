# 地图画石头熔炼批次

通过 Kit 现有 `material_jobs.processing.smelt`、熔炉读数、槽位交互和保护租约，在已经建成的新 16 炉中每炉投入 20 个圆石、2 根烈焰棒。32 根烈焰棒燃烧时长按当前 26.1.2 `FuelValues` 校验为每根 2400 tick，仅显式 `fuel_allow_items` 启用；默认燃料仍为煤和木炭。

本批实际收取 320 个石头，背包石头由 2 增至 322；圆石由 322 降至 2，烈焰棒由 32 降至 0。16 条炉子收取记录均为 `collected`，无未解决槽位操作。旧炉子和旧炉内物品保留。相关 Python 离线回归 1548 项通过。

收取熔炉输出会释放经验。本机配方 `data/minecraft/recipe/stone.json` 规定每个圆石产生 1 个石头、200 tick、0.1 经验。因此保护背包时不能把带经验修补装备的耐久上升直接当成物资丢失。本次靴子耐久 469 → 481、头盔 393 → 407；物品、数量、附魔及其他元数据保持原样，其他装备未变。接受这类变化须校验同一装备的经验修补、耐久只增不减且不超上限、实际完成的收取记录，以及所有非目标物品守恒；不能用修补理由放过损耗、装备替换或未知物资变化。

原控制器的严格装备比较因此停止收尾；原始错误和已完成收取账本均保留。之后连接因未知数据包 id 118 断开，日志与健康锁确认是普通网络断线。恢复连接后，用新世界两次当前背包观察独立确认完整数量与元数据，再启动新的保护收尾。没有重放原世界的装料、收取或收尾操作。

当前世界的原生 `KEEP_PVE_GUARD` 回执证明高空驻留、HP20、饥饿20，背包及装备保持接受后的状态。地图施工再使用单独的新批次，开工时重新核对当前服务器地图层，不从熔炼完成推断地图完成。

本地证据：`work/live-20261004/smelt-stone320-92a4-engine183-001/processing/batch-0001.json`，以及 `work/live-20261004/stone320-reconnect-accept-park-7f26-001/` 中的独立接受、两次背包观察和原生驻留回执。地图最终验收仍要求 16512 格实物及真实地图数据。
