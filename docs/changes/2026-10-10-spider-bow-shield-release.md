# 收盾后拉弓不同步与垂直瞄准等待

实际游戏：Minecraft 26.1.2，宿主 2026.10.9.3。本次修复仅运行引擎 1.7.95，保持 API 3，可原生热加载。

2026-10-10 02:18:57 至 02:19:21，蜘蛛 UUID 对应实体 315197644 的日志记录了 17 次放箭意图，但没有确认死亡。当前库存弓耐久为 365，采集批次开始为 370（无限 I、冲击 I，没有耐久附魔）；这不能支持所有 17 次都真正射出。02:19:21 实际手动移动接管停止了控制器，随后防护关闭，旧“拉弓反击”状态文字不能当成当前攻击仍在运行的证据。保留采集获得的 22 个圆石与原采集等待回执。

确认的代码缺陷：`BorerMobs.lowerShield` 只清使用键，射箭路径随后调用 `player.stopUsingItem()`。26.1.2 的客户端 `stopUsingItem` 只清本地物品，而服务器 `LivingEntity.startUsingItem` 在已有使用状态时拒绝切换手。因此盾到弓需要普通 `MultiPlayerGameMode.releaseUsingItem`，再开始普通主手 `useItem`；不能仅修改客户端状态或把排队点击当成已开始拉弓。

修复：收盾通过原版释放交互通知服务器；选弓前先释放真实正在使用的盾。拉弓直接调用普通主手交互，并从实际使用物品计算 `drawing`。放箭仍要求实际拉弓至少 20 tick、当前目标、弹道、最近可见画面和第一人称相机检查；日志明确区分释放意图与服务器确认。

同一次日志显示 wanted yaw -110.820045/pitch 89.45271，相机 yaw -236.9443/pitch 89.84833。两条射线实际都接近正下方，逐项比较 yaw 会误拒绝。改为比较两条视线方向的夹角，保持 6 度限制；仍拒绝过期画面、未知相机和实际相反方向。

回归覆盖：盾释放必须调用原版服务器交互、选弓顺序、按实际使用状态拉弓，以及上述真实垂直角度、相反方向、水平角差、画面时效与取消后的重新验证。实机击杀需要另行取得真实箭或伤害/死亡证据，不能以构建成功或放箭意图冒充。
