# 原图流水、单半砖与跨站放置回执

单格投影放置继续使用正常Minecraft/Meteor交互。27.8新增显式流水漏斗模式，28.1新增单半砖方向预测和跨站累计ACK；都不写入虚假方块或伪造库存。

## 流水漏斗

`projection_air_seed`可携带布尔值`replace_flowing_water=true`以及精确的`expected_current_state`。目标必须仍是原图中的漏斗、实际观察到的非源头流水；水源、岩浆、含水容器或其它方块不放行。原生检查周围已加载水源，发送前和确认期间都须保持原样，并在回执`water_source_baseline`中公开受保护位置与状态。玩家眼睛须露出水面，氧气至少75%，保持健康、PvE、范围、射线、实体及原图绑定检查。

`classify_flowing_water`只用于明确的控水施工核验：最多四个局部范围，每个最多5000格。它单列范围内水/空气更新，仍拒绝水源丢失、容器或其它结构改变、范围外变化；水流变化本身不能算目标完成。原始前后状态与所有变化继续留档。

## 单半砖

`projection_single_slab_air_seed_protocol=1`表示支持干燥单半砖。下半砖使用UP面，上半砖使用DOWN面；发送前必须通过Minecraft实际BlockPlaceContext预测，位置与完整方块状态均须等于原图。双半砖和含水半砖不能走单物品路径。确认仍需一次发送后的服务器更新、完整形态一致和恰好一个物品的库存变化。

上下半砖选择有离线回归；本次服务器实机验证覆盖两块下半砖顶盖，上半砖的服务器验收不能由此推断。

## 多站计数

旧`professional_printer.server_confirmed`仍保留每站含义：每次打印器启动会归零，不能作为多站总数。新增：

- `server_confirmed_epoch`：本次客户端进程内的计数标识。
- `server_confirmed_total`：只在原有pacer收到新的有效服务器确认时递增，换站不归零。

`printer_acknowledgements.acknowledged_delta`要求前后进程标识、世界会话一致，计数为非负整数且不倒退；不接受旧版缺字段、布尔值、重启或跨世界数据。它计的是确认的交互次数，多次交互形成的双半砖不能当作同样数量的目标格。场景匹配、资源守恒和最终运行验收仍须独立进行。

## 验证与边界

2224项Java源码检查、同数量的无源码回退安装包检查通过；ACK与流体场景相关15项Python检查通过。流水漏斗、跨站打印及两块下半砖顶盖均已有实机回执、库存与现场核验。

普通巡航的到达高度容差没有在此版本修改。水面作业必须重查实际位置、头部是否入水与氧气；不能把“navigation ended”当作精确站位证明。这些能力的验证不等于整座机器已经完成或投产。
