# Clef Flash 单人生存试验

Kit 宿主 2026.10.7.5；引擎保持 1.7.83 / API 3。用户创建并进入了“新的世界”，实际存档
位于 HMCL 26.1.2 隔离实例，普通生存、困难难度、初始空背包。任务通过原生 API 绑定
该存档并由 Minecraft JVM 启动 Python worker，长期目标为击败末影龙。

## 本轮交付

- 游戏内“单人通关试验”页，以及相同开始/暂停/继续/取消生命周期的原生 API / CLI。
- 复用正常 `walk_path`、`mine_block`、合成、熔炼、食物、站点和庇护所技能；有限扫描
  为 21×13×21。模型选择宏步骤，不会每个方块或点击都调用。
- 绑定真实存档路径、trial/run、当前会话和控制版本，拒绝服务器、LAN 发布或其他存档。
- 允许此试验正常死亡并用正常 respawn 请求恢复；死亡前的未决请求保留，不自动重放。
- 暂停立即停止自己持有的原生输入；持续模型服务和试验 worker 独立于 ChatGPT。
- Kit 经验数据库记录真实前后状态、原生回执及模型选择的固定经验提案。第二世界只导出
  相容环境下的建议，不包含第一世界坐标、请求 ID 或可执行代码，不自动提升成技能。

## 实机发现与修正

第一次探索已核对实际移位；下一条路线被原生落差检查拒绝。原桥把这种已确认停止的
移动与未知变更一同锁住，试验停在 pause。本轮仅为已匹配的 `walk/walk_path` 固定落差
拒绝且移动键全部释放的回执增加重新观察规则；旧路线禁止重发，部分移动不计成功。

反思输入增加真实粗略位移与原生终态分类，模型能够选择位置核对和失败后重新观察建议。
模型提案与实际观察分开记录；内存库写入错误也不会回滚已经确认的宏步骤。

实机还出现两个可行宏步骤的概率相近，模型持续选探索但 confidence 约 0.29–0.32，旧门槛
导致反复空转。本试验现在把低信心作为日志观察项；typed 候选与原生验证仍是执行条件。
近期目标明确为木材、工具、食物等里程碑，打龙保留为长期目标。服务器 Advisor 未改。

后台异常结束时释放自己的原生输入；已接收的生命周期请求保留 intent 与 reply，重启后不
重放。原生 API 也支持在世界已保存退出后正常关闭客户端。

CLI、能力清单、热更新、既有生存/合成及 Ollama 的相关 123 项检查通过。现场证据保存在

流程；没有声称已经通关或第二世界一定成功。真实胜利只读取当前 integrated server 中该

## 后续策略与热更新验收

新增精简能力表，逐轮向 Clef 提供当前可用宏的用途、前置检查、原生执行接口和实际完成
依据，明确保留未接入的通关阶段。图片和完整文字超过预算时自动模式明确退回文字，不
截断事实。

现场已通过 `singleplayer_trial_hot_update.py` 更换控制器：世界会话保持
`33c6fd45-fd0f-411e-ba7b-4f39b0e7b251`，只替换后台 run，Minecraft 未重启，经验库、
原尝试日志和检查点保留。证明文件为游戏目录的 `singleplayer-trial/hot-update-proof.json`，
并在项目现场证据目录归档。今后 Python 策略、能力说明和宏流程优先使用此热更新入口。

现场也记录了一次真实怪物攻击死亡：worker 始终由同一 JVM 持有，正常 `trial_respawn`
后原生状态由 `player_dead=true` 变为 false，生命恢复到 20，随后继续探索和采木决策。
这证明死亡恢复流程已实机运行，不代表已经具备成熟的防御或通关策略。

原木挖除已有真实服务端 ACK，地面也确有原木掉落；部分落点与树冠步行连通域断开，
尚未入包的原木没有计入采集完成。拾取优先级和正常下树路线仍作为试验修正内容记录。

后续已热更新 `collect_log_drops` 宏：优先收当前原木掉落，记忆位置必须重新发现实际实体，
库存增加才算拾取完成；不可达掉落不触发继续砍新树。仅对新扫描确认的干燥完整落点和
身体净空，尝试相邻最多两格正常下降，总路线不超过 32 节点，不开启 Flight 或挖出下树通道。
