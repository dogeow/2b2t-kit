# 指定船内诱饵的持续保护

为用户要求的直接捕获、运回僵尸，新增显式 `boat_uuid` 绑定。原本未命名目标的排除只有十五秒；现在同一目标实际进入指定普通船后，可以在同一有效控制租约内继续排除自动攻击，不必等待铁砧命名才能开始运输。

- 初次接管仍要求角色满血、目标为满血成年僵尸或合格溺尸、实体与控制记录新鲜，初次窗口仍为十五秒。
- 引擎从当前真实乘员关系判断是否已进入指定船，不通过改写实体状态或客户端伪造上船。
- 未上指定船、改乘别的船或船已失效，不能借此延长初次窗口。
- 路线内核仍要求精确的一名乘员、满血、玩家持有该船的真实缰绳以及完整船体、乘员和路线净空。排除自动攻击不等于承诺免疫日晒、碰撞、反伤或其它生物攻击。
- 人工接管、急停和租约失效继续撤销自动控制。

Java 测试 2132 项和相关 Python 测试 31 项通过。引擎 1.8.21 已经原生热加载，同一世界和进程保持，主包哈希未变，无游戏重启。安装证据见 `work/village-trading-20261017/live-village-096/hotload-boat-bound-capture-1495-proof.json`；真正的船内持续保护和新捕获运输尚未完成实机验收。

另修复了手动取消纯飞行后重新接手的入口：保留旧未确认飞行记录，不声称旧路线完成，不重放旧请求；只有原生明确显示人工取消、较新控制版本、原租约退出和当前健康空闲时，才允许从实际位置开始新路线。相关测试 2 项通过。

空船放置也可核对本控制器开始前实际已携带的不同船种。它仍须与历史未确认请求的船种不同、位置充分分离、库存数量守恒，且原隔离记录原样保留；只准备空接收船，不给予乘员运输权限。相关测试 9 项通过。

当前结果：尚未捕获新僵尸，旧暗室施工已按用户要求放弃，已确认的 52 格临时方块登记为待清理，清理前须重新核对现场与原有空船。后续继续找自然存在的目标，不恢复旧暗室方案。
