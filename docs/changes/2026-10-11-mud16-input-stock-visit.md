# 泥砖工位16格与一次预取原料

当前运行记录显示目标按全量配方峰值计算而缩到5、9，叶工位却实际采用四格子配方和16格访问预算，造成每4块就补麦/土或返图。新的只读 `mud_batch.carried_visit_target` 在完整当前世界背包、已授权泥工位和直装瓶水源、原生瓶接口、单空瓶、至少3空格及已有普通泥砖堆足容本批输出时，提供 `held+min(16, remaining)` 有界绝对背包目标。数量按真实剩余需求限制；物品模式、满包、命名成品堆、堆叠瓶、异世界及容量不足仍走原保守规划，不借未消耗输入当空格。

同一叶流程在这份容量证明下，每次工作访问只预取一次所需小麦/泥土，最多16。仍逐格正常装瓶、放土、转泥、挖泥，四份合成子批、全部物资守恒和unknown不重播保留。不得每轮把已消耗小麦补回绝对16；测试实际发现并修正该重复取料问题。

271项批次规划、泥流水线、材料调度/后端及平面图回归通过。新海水夹具证明初始2泥砖、零麦土，仅一次取16麦和16土，16次独立正常装瓶，最终实际18泥砖、原料清零；实际较小末尾目标仍按原目标处理。当前完整地图原16512格和最终16384像素验收不变。

产物已经构建并验证导入。当前旧控制器仍运行，正常取消只等待空工位、无pending、无保留水及已释放动作的安全边界，然后按原生高空收尾再安装；此文不把尚未安装的改动说成实机16格完成。
