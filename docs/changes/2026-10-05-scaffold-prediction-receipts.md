# Scaffold 服务器包与 Vanilla 预测收尾

旧控制器在 `serverBlock` 收到目标包时，因为客户端当前方块还没与包状态相同而将 `applied=false` 的包丢弃。Vanilla 可以先保留服务器状态，等待预测序号确认后才把它应用到世界；水桶接口已经保留这类包并等待预测结束。这个结构漏口已由源码确认，但不能据此断定它是历史单格 WAITING 的唯一原因。

宿主 `2026.10.5.1` 保留同连接、同 level、原世界／revision／owner、发送后准确目标的包，包括尚未应用的包。任何纠正或错误状态立即锁定失败，后续正确包不能覆盖它。轮询只调用已有 `BorerMiningConfirmation.pending(level,pos)` 读取预测范围，不启动破坏预测或同步手持物品。

一个格子只有在预测已清除、真实服务器区块仍加载、完整预期状态相同、累计物品减少与全部发送格一致时，才开始稳定确认。稳定起点是首次正确包、最后一次预测清除、库存重新准确三者的最大 tick；完整等待 8 tick 后才能增加确认数量。

- 没收到包：发送后 100 tick 等待并停止，不重发。
- 收到包但预测一直未清除或查询不可用：包后 100 tick 等待并停止。
- 单次发送的总体等待：240 tick；既有请求时限继续有效。
- 第 92／99 tick 收到的正确包不会被“无包 100 tick”截断其完整稳定时间。

新增 `attempts` 诊断记录发送、包、ACK、观测、预测清除与稳定 tick，以及包状态／是否应用、预测是否 pending、当前世界状态相同、服务器区块证据和 settled 状态。`failure_reason` 区分无包、预测、库存、世界状态、区块与总体时限失败。关闭后观测冻结，晚包不更新旧结果。

历史 WAITING、未决格和已确认数量保持原件；新读取不能补写旧 ACK。修复需更新主包并正常重启才能生效，源码、构建和实机证据分别记录。
