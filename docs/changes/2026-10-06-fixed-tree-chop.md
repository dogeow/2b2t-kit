# Kit 原生固定树砍伐

首棵自种樱花树使用了 Kit 的原生 `chop`。砍下 8 根后因树叶挖掘停住，随后才用原生单块挖掘接口维护剩余树冠。本次增加原生固定树入口，仍复用 `AutoChopper` 的砍伐、树冠复查、拾取、临时支撑回收和可选补种；没有用 Python 替代整套砍树逻辑。

已有 `chop` 增加可选的一组参数，三个坐标数组必须同时提供：

```json
{
  "op": "chop",
  "item": "minecraft:cherry_log",
  "target_count": 32,
  "tree_limit": 1,
  "tree_root": [761033, 69, 797882],
  "tree_min": [761025, 69, 797874],
  "tree_max": [761041, 91, 797890]
}
```

调用者需要当前材料 lease，沿用原请求的世界、revision、task_session 等控制封装。`target_count` 仍是绝对背包目标；固定批次只收一棵完整树，数量不足时不能说总材料目标完成。

固定模式直接从指定根查找自然树，要求根属于实际泥土树桩、所有原木属于指定树种并在边界内，以及边界对应的区块确为当前服务器区块。单根树不得合并其它独立树根；宽树种只接受指定根附近的 2×2 树桩范围。辅助树叶、草类挖掘和保留的树冠复查 witness 同样受边界约束。

根缺失、树改变、范围越界或树根含混时拒绝/停止，不退回最近树搜索。已启动的作业继续保留原树冠锁；本入口不允许用缺失的根凭空推断另一棵树，也不自动重放旧未知请求。原生树叶挖掘故障尚需后续实机复核。

材料 SDK 仅在宿主宣告 `fixed_tree_chop_protocol=1` 时，为已登记的自种樱花区域传入固定根和区域边界；旧宿主继续使用原有最近树核验。
