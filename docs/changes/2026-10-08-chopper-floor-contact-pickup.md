# 飞行拾取在地面接触时停住

版本：主包 2026.10.8.2；Chopper 1.9.53；引擎仍为 1.7.86。

在 Simpcraft 的已种樱花树林中，角色实际位于 `(760886.456, 67.000, 797976.470)`。拾取搜索能够生成路径，但每次执行都立即报告 `actual-body-collision`，两次重规划后停止移动。此次日志仅证明砍下 8 根原木、完成一个树遍历，背包原木为 0，不能计为成功收集。

原因是执行阶段将实际身体扫掠盒向三个方向同时扩张 0.005 格。角色正常接触 Y=67 的地面时，扩张把盒底压入 Y=66 的地块；搜索阶段的身体盒却保留脚下余量，两阶段因此不一致。

执行扫掠现在只增加水平余量，垂直范围保持真实身体和真实运动的并集。真正向下进入地面、碰墙、未加载区块、液体、危险块和实体仍会阻止路径。

退出树林的 Python 通道也改为使用实际悬停高度计算身体扫掠。原生导航可能在目标高度附近的非整数位置稳定，不能用必须接近整数的条件拒绝已核对的空气通道。完整身体、实体、库存、防护与原生到达确认要求保留。

验证：1855 项 Java 测试通过，包括此次实机地面接触的回归、真正向下撞地面和横向撞墙的反例；7 项退出通道测试通过。旧主包和平台记录备份后已安装新主包。安装完成不代表飞行拾取已通过新版本实机验收，后续需确认实际背包原木增加。

此次失败的平台坐标 `(760879,69,797969)` 已通过当前世界扫描确认为 AIR。原始停止回执与支持记录保留，不补写成功放置、不重放放置。角色通过同一控制者的实际空气通道升到约 Y=130，满血并完成原生 KEEP 停车后正常重启。
