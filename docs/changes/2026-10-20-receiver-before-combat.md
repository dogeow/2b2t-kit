# 空船捕获目标先于自动防御登记

现场日志确认，控制器尚未登记目标时，独立防护已经攻击并杀死靠近的成年僵尸。原来的 Python 轮询无法可靠抢在游戏防护循环前登记；未确认捕获不能记作成功。

引擎 1.8.23 提供一次性的 `capture-receiver.json` 登记。登记绑定当前世界、材料租约、玩家和一艘由玩家拴着的空船，有效期最长十分钟。游戏循环可先保护船边一只满血、成年、未命名、未着火且未乘坐其他载具的僵尸或无三叉戟溺尸。附近苦力怕、骷髅及其他目标仍走原有防御路径。候选需处于真实服务器区块，距船至多 18 格、高差至多 4 格；保护不执行移动、攻击、瞬移或回血。

原有明确目标登记仍要求防护空闲。空船登记允许防护正在处理其他敌人，因为它只撤销对单个满血目标的自动攻击。未上船保护仍限定十五秒；同一目标真实坐上指定船后，沿用同租约的船内保护。每次候选选择先持久保存 claim，订阅失败、手动中断、热更新或后续手动登记均不能重新执行这次选择。

Python 新增 `capture_receiver`。登记成功只是配置回执，不是捕获成功；捕获必须另有两帧真实乘客、满血状态和当前 `boat_bound` 回执。既有载客运输的完整空间、生命值、拴绳和未知回执保护不变。

另外补齐两个仅允许观察的恢复入口：放船交互在发送前因射线遮挡而被拒绝；以及已明确停止的空中导航随后发生小幅防护升高和有限普通怪物掉落拾取。它们不计抵达、不计放船、不重放旧请求，后续移动须重新选择路线。

已通过完整 Java 测试 2136 项及相关 Python 回归测试。1.8.23 已通过原生热加载，主包未替换、游戏未重启。安装证据：`work/village-trading-20261017/live-village-097/hotload-boat-bound-capture-1533-proof.json`。实机捕获和最终刷铁机产铁仍须另验，不以测试或登记回执替代。

本轮另已确认拆除刷铁机中央视线木板，并恢复施工临时外墙孔；现场原有诱饵船为空。西侧遮阳点及空船、拴绳的实际后续位置必须读取新车辆观测，不能复用旧坐标。
