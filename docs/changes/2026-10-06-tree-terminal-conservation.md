# 砍树停止后的材料收尾

首棵自种樱花树的实机记录显示：砍树因树叶挖掘停住时，仍有 13 根原木，但 `AutoChopper.stop()` 调用 `clearTree()` 后公开的剩余计数归零。材料流水线原先只检查剩余计数和临时垫脚数量，可能继续尝试补种。

采集器现在先保存本次原生砍树请求的 ID、世界、阶段和说明。只有原生 `done`、控制器已停、剩余树木和垫脚计数均为零，才进入原有补种流程。`stopped`、`waiting`、`error` 或仍在运行均保留原树在途记录，返回 `tree_harvest_not_finished`；不会因为背包够数而把停止回执改成成功。

同时将现有在途记录检查移到“背包数量达标”返回之前。已达到材料目标也不能消除另一条尚未核对的采集请求；原记录不变，不发送新采集动作。

回归覆盖停止后计数归零且背包恰好达标、三种非完成阶段都不补种、再次进入不重放，以及矿物库存达标仍保留原在途记录。已有正常整棵砍树与补种用例继续通过。

专项采集与补种回归 64 项通过，完整 `check_offline.py` 1551 项通过。

这次修复不解决原生砍树的树叶挖掘故障，也不把离线回归当作实机砍树成功。首批木板施工程序曾因游戏的“用户界面接管”保持只读等待；界面关闭并持续空闲 5 秒后才取得新的材料 lease。部署采集器修复继续等待本批动作控制者完成，不在施工时替换其 SDK。
