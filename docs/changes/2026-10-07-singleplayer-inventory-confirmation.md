# 单人试验背包点击确认

一次菜单0槽位11的原木点击收到宿主`settle/done`后，SDK等待6秒仍没有看到原木移到
光标。旧宿主的8tick定时完成不代表服务器处理过点击，也不能证明点击没有发出。
原请求和失败实机帧已保留；没有重复点击或关闭菜单来猜测恢复。

`2026.10.7.8`为单人试验的InventoryMenu/CraftingMenu增加`inventory_confirm=true`协议。
游戏仍通过正常`handleContainerInput`发送一次点击。只读观察绑定实际发出的点击包，
编码成功后按当前连接FIFO核对服务端收到的完整包，并在真正执行`menu.clicked`
之后记录服务器状态。取消、外来包、队列溢出、跨会话或状态不一致都保留未知结果。

回执区分物品变化已确认、服务器已处理但没有物品变化、结果未知。完整物品组件、
光标、原料槽和玩家库存参与比较；合成结果槽0允许由服务器稍后计算，最终客户端
和服务器仍须完整一致。普通服务器与炉子保留已有路径。

SDK在派发前写入磁盘待确认记录。原生确认通过后，还需SDK谓词在两个时间前进的
真实帧中成立，才能写入提交回执。进程退出不会把尚未确认的点击变成完成，恢复时
继续保留该记录。毫秒时间允许相等，真实包顺序负责证明因果。

`inventory_probe`是独立只读入口，在集成服务器线程读取实际玩家菜单和库存；它只能
证明当前状态。单独的`trial_inventory_audit.py`核对旧JVM正常保存并结束、新会话的
完整43格库存、空光标和合成格，允许从新实物基线重新规划。历史点击仍未补确认，
原请求编号持续列为禁止重放。新后台在复核通过前只启用防护。

本次启动器磁盘日志只记录`ProcessStoppedEvent`，未直接观察退出码。退休审查因此
另外支持真实退出请求与回执、完整保存、进程终止和停止日志的组合证据，明确保留
`exit_code=null`。这只允许读取新实物并重新规划，不补旧点击确认。

完整1827项Java测试、308项相关Python测试、JAR和引擎分离校验通过。此修复涉及
宿主及Mixin，需要一次保存和重启；Python策略仍可独立热更新。实机安装、原木合成、
门与小屋的完成结果另行记录，测试通过不代表这些游戏目标已完成。
