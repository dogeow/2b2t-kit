# 本地补光、补火把与严格回执流程

`kit_cli.py lighting resume --profile PROFILE --auto-supply --torch-target 128 --max-supplies 32` 可在缺火把时通过独立 material-task mailbox 启动原生火把材料任务，再续跑原分区日志；不使用模型、截图或按键。先等已有补光 worker 的实际 flock 释放，不建立第二个行动控制器。

补料请求在发送前写入原 id/世界/目标。启动命令被接受不等于完成：须同一任务实际 completed、process_alive=false、occupied=false、同一世界实际背包达到目标、满血和当前所属 guard parking 都符合。超时或状态未知保留原请求、禁止重新发送。人工移动、健康锁、世界变化、外部控制、补料 paused/blocked 或未知放置都会停止继续任务；不解锁、不自动重连、不自动重放。

局部恢复仅适用于两个证明过的读预检：被动实体挡路、已有防护等待超时。使用原 request/event、全部已验证放置的原 intent/双帧与精确库存扣减、仍属原任务的当前满血高空 parking 来核验；保留旧 pending 和证据，不把整个分区标为完成。其它未知动作仍待核对。

实机溺尸被现有防护处理，约 32 秒后观察到 health=0，期间玩家保持满血；旧 20 秒等待提前停止。等待改为 60 秒，仍要求伤害/接管/离开世界优先停止，且只能在防护与存活怪物均平息后发送补光输入。回归涵盖超过 20 秒的正常战斗、60 秒超时、人工接管和状态异常。

68 项补光、供料、预检和 CLI 回归通过。170 文件 bundle 已在原进程终止后备份安装，宿主不变、无需重启。直接使用已安装 Kit CLI 启动了自动补料工作流，补光已续跑；首次真实缺料补给尚未发生，不能称为已实机验证完整补料闭环。

实际耗时需采用正确单位：Python events.jsonl 的 time 为 Unix 秒，原生 status.time 为毫秒，duration_ms 为毫秒。近期批次统计显示放置接口约 0.6 秒一次，多数时间在移动与扫描；不能把减少安全检查或错误声称完工当成提速。详细当前统计在补光输出 timing-20261003.json，包含其有限采样范围。

分区遍历结束后仍进行全部授权区域的当前亮度复核；coverage_complete 只表示审计覆盖，剩余暗区、保护区域边界与地图画完成须单独核实，本工作流不会把全目标标成完成。
