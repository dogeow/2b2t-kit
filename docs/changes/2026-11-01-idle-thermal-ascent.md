# 待机热伤先升高，施工期间保留原作业策略

用户明确要求：除非正在施工，否则待机被烫到应先飞起。引擎 1.8.41 在独立 PvE 防护中增加待机热伤恢复，不修改宿主或 Mixin，可热更新。

仅新鲜同世界/服务器的状态确认没有活跃施工、打印模式、移动或控制器时触发。已经结束、正在收尾的材料租约可以进入待机恢复。物理移动/使用/攻击、界面、新的待处理动作、生命安全锁和危急保护优先；现有施工控制器的轻微热伤策略保持原样。

遇到火焰、余火、篝火或岩浆块热伤，沿已加载且无碰撞的竖直空间最多升高三格；天花板会缩短上升范围，没有可用空间则记录阻挡，不穿过方块。使用正常 Meteor Flight 与跳跃输入，不瞬移、不伪造位置、不解除安全锁。临时降低飞行速度，结束后仅恢复仍由本功能持有的设置；保留飞行悬停，防止落回热源。一个持续余火事件只升高一次，之后由已有进食/回血逻辑处理。

状态记录位于游戏 `config/twob2tkit/automation/idle-thermal-ascent-state.json`。`watching_idle` 表示待机监测，`rising` 表示正在升高，`done` 表示已达到本次安全上升高度；`no_clear_ascent`、`ceiling_or_timeout` 等保留实际限制。

实际候选引擎通过 76 项相关测试，覆盖施工/打印/人工优先、过期和跨世界数据拒绝、有限上升、飞行设置恢复及引擎/导航热重载。完整 Gradle 离线检查在编译前因缺少 `fabric-loom 1.17-SNAPSHOT` 缓存失败；隔离产物由当前已安装引擎制作，验证未混入他人未提交的 `BorerThreats` 改动。未刻意让角色再次受伤进行危险实测。

## 1.8.42：查询不占用运动控制

统一快照读取与逐帧检查的待处理动作分类：只读扫描、投影审计及截图不会取消正在进行的待机升高；同世界、未确认且未过期的施工动作仍优先。新增两项回归，实际候选引擎共78项相关测试通过。
