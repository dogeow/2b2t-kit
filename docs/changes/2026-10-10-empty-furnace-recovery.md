# 回收新增地面熔炉

用户要求减少地面熔炉。宿主 2026.10.10.1 / 引擎 1.7.95 / API 3 新增 `empty_furnace_recovery_protocol=1`，允许正常 `mine_block` 携带 `recover_empty_furnace=true`，不开放普通容器挖掘。

回收必须绑定同一材料任务通过普通交互打开的具体炉子。当前连接的服务端完整容器包和后续槽位包证明输入、燃料、输出三槽为空，实际菜单同样为空且游标为空；炉子未点燃、邻接没有漏斗或液体、附近没有其他玩家，热栏镐耐久至少 32 且背包有拾取空间。请求提供当前菜单编号、内容观察序号和热栏镐位置，检查通过后正常关闭菜单并开始原版挖掘。挖掘过程中继续验证工具、周围环境和生存条件，完成仍依赖既有服务端方块更新及正常预测序号确认。

`furnace_recovery.recover` 先把炉内所有材料正常转入背包，再等待实际冷却和服务端空槽证明。每个炉子分别保留挖掘、拾取和实际库存增量证据；未知结果保留原请求，不重挖、不重拾取。现场已有炉位后续继续复用，新增 16 台回收物存入已登记仓库。

现场用户已换下界合金剑，旧开炉／开箱函数固定找钻石剑导致选择被明确拒绝。`container_hand` 从实际携带的剑中选择正常容器交互手持，并核对选择结果。可见面若被原生接口明确在交互发包前拒绝，仅在同一世界、任务、空菜单、游标和防护条件下重新确认另一个面，最多一次新交互；超时、未知结果和异属回执均不允许重试。

完整 Java 回归 1890 项通过；Python 回归覆盖实际剑选择、开箱、熔炉加载、发包前可见面／点燃状态变化，以及未知回收保留和精确物资增量。宿主已备份并安装，经一次健康高空正常重启返回原生存服；实际回收验收以当前回收账本为准。

实机新增 16 个炉位已移除，15 台正常拾取并存入已登记仓库；第 4 台挖掉后的掉落物未入包且随后消失，原等待记录保留，没有记成回收成功。炉内 3 块牛排和 8 根木棍正常取出保留。正常步行下一格台阶解决了“格点接近后掉落物仍在拾取范围外”的情况，保留旧 `collect_item` 等待，不再重发拾取请求。

清空后客户端预测与服务端一致时，原版可能不发送冗余槽位包。重新正常打开一次同一炉子，取得新的完整服务端空库存；不以本地空槽替代证明。后续以实际已验证的高空停靠点收尾，允许原生地面升空把停靠高度重新绑定到当前安全位置，不再在已安全的高度循环等待旧固定高度。

Python 相关 59 项回归通过；6 个共用 worker 模块已逐文件备份、部署并更新对应清单哈希，无需再次重启。炉子回收、正常高空在线待命和材料保存均有当前世界回执；完整地图画和最终地图物品仍未完成。
