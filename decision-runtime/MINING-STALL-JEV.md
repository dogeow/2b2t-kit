# 区域自动挖矿卡点与 Jev

AREA 挖矿确认卡住时，原生控制器先松开挖掘和移动输入，保留安全悬停；原有 PvE 防护仍先于区域挖运行。卡点记录到游戏目录 `config/twob2tkit/jev-mining-stalls.jsonl`，用于复盘和修正 Kit。Jev 只给诊断建议，无论选哪项都不自动重试、重扫或恢复移动；需要玩家明确停止并重新开始。无密钥、网络失败、超时、答复不确定或没有安全候选时也保持暂停。

实际 Jev 请求**默认关闭**。获得对以下字段和目的地址的明确许可后，才可在游戏目录 `config/twob2tkit/jev-mining-opt-in.txt` 写入唯一一行 `area_stall_v1`。代码不会自行创建这个文件。已存在密钥也不会绕过此开关。请求目的地址是 `https://api.typesafe.ai/v1/systemone`，模型和响应格式沿用本仓库 `decisions.py` 的 Jev 契约。

发给 Jev 的 `state.scene` 只有这些固定分类：卡点原因 `aim/mine/move/server_ack/pipeline_ack`、挖矿阶段、无进展秒数、工具类、方块类、背包容量档、血量档、服务器确认类别。另附原生控制器能安全评估的固定诊断候选：`pause`、`wait_once`、`retry_once`、`rescan`。不会发送玩家名、服务器名或地址、世界名、原始日志、存档内容、精确坐标、物品清单或 API 密钥。Jev 只能在候选 ID 中选一个；本版只记建议，不执行。服务器未确认的破坏只提供暂停或等待的建议，不提供重挖或重扫。失焦时若血量、威胁和手动状态仍安全，可以记录匿名建议，但游戏始终暂停。

每个确认卡点只询问一次；同一局部卡点在 60 秒内可复用答复，不设每小时调用次数上限，也不创建预算文件。每个事件记载脱敏提示摘要、候选、Jev 答复的模型/置信度/概率/用量、原生暂停回执及明确重启后是否出现确证进展。
