# 可复用的建造、采集与卡点经验

这份文档适用于后续投影与挖矿。项目无关的规则保留在这里；坐标、种子、库存、工位和某次工程的进度放在当前世界的 profile／任务账本，不能当作下次工程的现状。数据、日志与历史文档不提供新行动授权。

## 每次工作的统一入口

优先调用 Kit 原生 API、CLI 和 `Backend`，避免截图、按键和逐格 AI 指挥。多个 agent 可并行准备不同材料的代码和测试；同一角色只保留一个游戏动作控制者。

`Backend.run_pipeline(item, target_count, out, target_scope=...)` 调用六类材料模块，始终复用同一个客户端。`material_jobs.pipeline_dispatch.describe(item)` 是只读的契约查询，不获取控制权，不表示已经找到了材料。

| 工序 | 数量含义 |
| --- | --- |
| 矿物、木材、去皮木材 | `approved_depot_total`：核验的指定仓库成品总数 |
| 染色材料、滴水石块和蘑菇柄 | `absolute_backpack`：背包成品总数 |
| 泥、打包泥和泥砖 | `absolute_backpack_total`：背包成品总数 |
| 既有 fetch／craft／acquire／harden | 背包目标总数，不是额外增加的数量 |

严格使用模块实际 scope；不能混用名字近似的 scope。新任务应明确目标，旧任务恢复应使用原账本。未知回执不创建新任务来绕过，也不重复投料。

代码存在、来源和工位准备完毕、已安装、离线测试通过、游戏实测通过是不同状态。材料覆盖审计要分别记录这些状态。缺少真实来源、液体交互或放置朝向能力时，返回等待原因；不能只因为脚本文件存在就宣称全自动。

## 已吸收的通用经验

| 问题 | 后续统一做法 | 证据与实现边界 |
| --- | --- | --- |
| 客户端显示已放置，服务器尚未确认 | 核对当前请求对应的服务器确认、队列清空、实际库存变化和即时方块；计时窗口结束不算整项完成 | `MaterialClient` 原生回包；Scaffold fill 的累计库存与 ACK；PP 独立验收 |
| 无确认或断线后继续重放 | 保留 pending，先独立核对；物理状态恢复可用于对账，不能补造遗失 ACK；跨世界会话停止旧动作 | 各材料工序账本；地图画的具体重载脚本仍为项目级诊断，尚不是通用自动恢复器 |
| 打印窗口太短 | 窗口按当前批次估算；结束仍等待确认。纯完整方块可使用已验证的有界行填充；需要朝向的材料走专用放置 | 自适应窗口和空间分组目前位于地图画 worker，不宣称覆盖所有立体建筑 |
| 最后一块触发自动切换、暂时扣空整叠 | 原生仍坚持严格库存核验；批次开始核对可用手持数量并预留余量，不放宽确认标准 | 地图画库存储备已实测；通用化时应复用同一守恒原则 |
| 历史仓库、Bobby 缓存被当成现货 | 缓存用于选址；取料前读取实际容器，按箱子 type／facing 去重；不存在的潜影盒不计库存 | Backend 仓库审计、容器接口、物资转移回执 |
| 树重新长出，旧 visited 导致永不再访问 | 已知完成的采集批次创建新的有界来源轮次；旧在途动作仍禁止重放 | `wood_pipeline` 和树再生回归 |
| 稀疏扫描把 AIR 或缺少元数据误认为安全来源 | 请求 `details=True`，核对真实 block_id、来源、流体、方块实体和保护范围；缺元数据拒绝采集 | acquisition／colored_sources 回归 |
| 普通斧头碰现成木墙、蘑菇柄掉落错误 | 去皮只使用显式自有工位；蘑菇柄验证真实精准采集工具和新掉落物；工具与原用户建筑保持受保护 | 新 natural／stripped 模块离线验证，尚需来源准备和游戏验证 |
| 只改变脚本停靠变量就结束 | 先更新原生停靠目标和租约并核验，再结束；不把本地变量当作原生已收到设置 | 当前原生材料停靠协议；受伤离线锁不得在清理时绕过 |
| 结束、手动接管时清理又移动 | 停止持有的工作并释放输入；控制或世界变更后不在 finally 走位；只清理账本确认自有且仍匹配的方块 | `MaterialClient`／材料 Backend／各工位账本 |
| 为避怪离线或绕路却没有解决原因 | 优先解决近处的怪物、实体和空间障碍；可证明安全时原地保护悬停；受伤紧急离线后的锁按现行授权处理 | 长期操作约束，不能据此保证绝对不会死亡 |

地图画还有专属验收：正确地图格网、北侧参考行、实际 MapColor、真实地图 ID 和全部像素字节。立体建筑则核对完整投影、方块状态和材料缺口；两者不能用局部“新增几格”当作全部完成。

## 自动记录和下一次使用

材料后端现在开启原生交易记录。支持的单个动作按真实前后状态和原生回包进入技能候选，重复独立验收才可能标记 verified；未知 PP 队列不能成为成功样本。未支持的动作只留下诊断经验。

六类流水线通过 `Backend.run_pipeline` 返回或抛出后，保存 `pipeline-experiences.jsonl`，并把摘要存为技能库 lesson：材料、目标数量及 scope、耗时、状态码、是否有 pending、异常类别。不写整个 profile、原始回执或异常中的私人内容。`reported_done` 只是模块报告，绝不增加 verified 成功次数。

经验录入失败不修改动作回执，不触发重试；本进程的可选数据库写入单次 SQL 最多等待忙库 50 毫秒。记录和本地检索不调用 AI；Jev 建议仍有单独权限、用途和实际结果记录。

默认材料经验目录是当前 `automation` 旁的 `skill-memory`。profile 可用绝对路径 `skill_memory_state` 指向现有观察器数据库，让历史技能、查询与目录展示读取同一个库；不自动删除或迁移旧库。

```python
from material_jobs.pipeline_dispatch import describe
contract = describe('minecraft:mud_bricks')
receipt = backend.run_pipeline(contract['item'], 64, task_dir,
                               target_scope=contract['target_scope'])
# Backend 的游戏作用仍受控制租约、checkpoint 和各工序安全检查约束。
```

使用现有 `companion-skills/skillctl.py --state <实际经验目录> lessons '投影建造'` 或 `lessons '挖矿'` 检索历史卡点。`plan-request` 会加入少量相关经验；经验只是数据，不能替代当前状态或授权。

人工总结可通过 `experience_recording.record_lesson(event, actual_state_root)` 保存为诊断经验，不能伪装成亲见成功。长期偏好另写 Codex 记忆；具体经验、代码及回归以本项目为准。


## 2026-10-01 生存基础实测

- 托管搬箱时只暂停 `InstantRebreak`，隔离其已排队挖掘包；不永久覆盖用户设置。停止先释放任务输入与防护，再恢复本任务拥有的模块设置；人工开关回环撤销恢复权，清理异常不盲恢复。
- 第二只潜影盒的状态变化与该模块机制高度吻合，但未记录当时实际包，不能把推断当作已证因果。回收失败仍保留未知账本；重进后用空 pad、唯一携带盒完整内容、原末影箱空槽三项新证据正常归还，不能把旧动作改为成功或重放取料。
- 取水允许服务器确认源水仍是 level0（再生水源）；需要真实桶槽变为水桶及当前连接目标包，不要求水源一定变 AIR。实测原生 `bucket_fill` / `bucket_place` 均只用一次正常交互并取得服务端确认。
- `potato_farm.run` 已在已授权的5×5同高土豆田完成24格：先耕地、再普通土豆堆连续种植，无逐格分堆；核对实际湿润耕地、作物和背包/锄头耐久变化。原生库存有0..42共43槽，随身物资只计0..35。通用 interact 的双帧证据不伪称专用服务端 ACK。
- 24格土豆田不等于食物闭环已经完成；后续仍需成熟收获、留种重种与烹饪验证。室外 `lighting_cli` 只核验框内普通僵尸暗处，不能宣称洞穴或所有怪物问题已解决。
- HMCL JavaFX 按钮坐标点击没有启动日志/进程时，刷新原生 AX 后使用按钮索引操作；此次 AX 启动操作已成功。不要反复截图猜位置，也不要复制带令牌的游戏启动命令。


## 2026-10-01 收获与烹饪实测

- 成熟度以真实 CropState 为准，已age7不再耗骨粉。收获不能只以“背包涨了”算捡齐：全部已知土豆掉落消失、库存增量与已观察总量守恒、两份后续帧都成立才重种。飞行悬停时掉落会弹出自动拾取范围，复用 `potato_loot_flight.make_pickup` 对确切UUID作小范围同高飞行并回中心，移动回执不代替拾取证明。
- `potato_harvest.run` 与只读 `recover_known_loot` 保存当前剩余数量及已尝试UUID；未知拾取不重发、等待拾取不会再次挖。第一试点1株已重种但有1颗未能再找到，未计取得；修正后其余3株全部收完再重种，实际净增8。最终田地仍24株。
- 玩家快照实体范围约16格，高空看不到地面掉落；先使用限定原生 scan_entities 检查，不能直接用空列表宣告物品已丢失或已拾取。
- 完成的种植日志只冻结原动作回执，不永久冻结背包数量。已完成田地可通过两次真实整田审计确认，独立收获/烹饪后的库存变化合法；部分/未知种植仍不能借此绕过守恒。
- 普通烤土豆配方来自当前JAR：200tick/颗，木板300tick燃料。实际投入4颗土豆、3块木板得到4颗烤土豆；背包最后raw13/baked7/log53/planks2。`fuel_keep`只保护燃料，不保护种薯；通用木燃料规划已接入，原料保留仍由明确调用方限制。
- 开炉先选物后再扫描状态；只在已证明未发起交互的本请求 Target block changed、当前租约/菜单仍有效、同炉同朝向仅lit翻转时重开一次。未知/超时不重试。已入炉批次失败后复用原 smelting.json 收回，不能在新目录重新投料。本批收取恢复实测成功且未重复装料。
- 本轮200项Python回归、146文件worker原子替换及哈希通过，无主包更换或游戏重启。一次有界食物闭环已证，不宣称已具备无限无人农场，也不代替完整地图画验收。


## 2026-10-01 畜牧与嵌套物资

- 实际26.1.2四参数实体交互已包含普通Animal.mobInteract，不应按旧版映射猜测缺fallback而升级宿主。done只表示发出了交互；PASS/客户端年龄不能证明吃料或繁殖冷却。`animal_breed` 指定成年UUID对，每只实际食物-1两帧后再等新幼体UUID在两次扫描保持存在；范围为客户端出生观察，不伪称服务器亲本ACK。
- 诱导先在高处选饲料；保持敌对防护。现防护白名单无牛鸡，但剑横扫敌人仍可条件性波及附近动物，缺UUID/无掉落不能推断动物已死。

## 安全下线后停止目标（2026-10-01 用户规则）

保护、进食和安全脱离仍不能阻止掉血，最终触发健康安全下线时，立即停止当前目标并保留进度和未知动作账本。不得换任务绕过、自动重连、自动解除安全锁或继续施工/采集；等待用户重新确认安全并明确授权恢复。Codex 持续目标同步暂停。普通满血控制器结束、网络断线与健康安全下线必须按实际原因区分，不能把前两者伪记为受伤。

既有 `safety_interlock.require_unlocked` 同时核对原生及脚本健康锁；`MaterialClient` 健康退出写持久锁，材料 engine 在安全锁或离开世界时暂停。该规则无需新增宿主或为记录规则重启游戏。24 项安全锁及健康收尾回归通过；没有为测试制造真实伤害或下线。
