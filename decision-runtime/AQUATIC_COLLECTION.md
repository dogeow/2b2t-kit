# 水下连续采集

## 游戏内入口（Kit 1.9.87）

打开工具箱（默认 U）→「挖掘」→「采集沙砾」→「开始水下采集」。这是 Kit 原生 client tick 任务，不需要启动 Python，不依赖星舰坐标或投影。数量、扫描半径、最大深度直接在首页编辑；应用后开始。数量 0 表示背包满再结束，当前用户配置为 0，半径 12、深度 12。

正常停止用同页「停止并上浮」，先返回当前海面上方安全高度并保留防护；方向移动键和紧急停止立即交还控制。该模式要求生存模式、主世界、满血和足够饥饿值、食物、水下速掘／水下呼吸 III 头盔、深海探索者 III 靴子、耐久至少 100 的精准采集铲子。支持本地世界及用户已确认允许自动化的 Simpcraft。扫描范围限定在启动点附近已加载的海床；浅水与岸边使用页面下方的陆地找矿入口，保留原多矿选择。

有界实测已验证：直接点击按钮采集 4 块、背包实际增加 4、达到数量后高空收尾、生命始终 20；「停止并上浮」按钮也已验证。还实测过同次潜水连续 6 块。若附近无安全目标、掉落漂出安全拾取范围或连续三次无法确认入包，任务会停止并提示；不把客户端方块消失当作材料进度。完整记录在当前工作区 `outputs/starship/work/release-1.9.87-native-gravel/`。

## 返气与采集约定

氧气以游戏 `air_supply / max_air_supply` 为准，一格气泡约为最大氧气的十分之一。返程目标是到空气中仍留一格余量；不能等水下只剩一格才开始上浮。

- 材料任务下潜后调用 `air_return_set`，登记当前位置上方实际能呼吸、区块已加载且无碰撞的返气列。路线限当前世界、材料任务、装备和短有效期。
- 原生层先采集同一世界和装备的三份真实上浮样本。样本不足时保持旧的保守预算；有证据后按深度、实测耗氧及延迟余量输出 `air_return_floor`、`air_pickup_floor`、`air_work_floor`。
- Python 的 `dive_safety` 只接受仍有效的原生观测预算。挖掘预算包含后续拾取成本，拾取单独使用较低门槛；过期或错误预算不能放宽安全限制。
- 到返气线由 Kit 自行中止采集并优先竖直上浮，脚本暂停或两条命令之间也会检查。路线失效且无法确认安全上浮时走安全下线，保留低血量锁和手动接管。
- `ocean_pickup.select_next_gravel` 按真实距离选择可挖、可捡且下方有支撑的邻块，跳过不合适的候选；背包增量才算采集完成。

无药水流程需要水下速掘、水下呼吸 III、深海探索者 III 和可用铲子。原始观测、操作耗时、每块入包与返气结果写在运行回执里；这份文档描述实现约定，具体版本的实机验收以对应回执为准。
