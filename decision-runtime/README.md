# Minecraft typed decisions

当前使用入口：双击桌面 **Minecraft AI 体验.command**，选择 **6：启动/托管选中投影**。普通生成地图和 Simpcraft 的首轮实测见文末；3～5 是早期开发入口，不代表已实现普通地图自主通关。
Jev 已接到 Kit 的本地动作接口；Laya-MLX 可用来做本地比较。这里不启动后台模型服务，不唤醒 Codex 任务，也不恢复已移除的 Spark 反馈。

当前支持：实验性的本机生存开局任务循环，以及从给定候选中选择动作、读取概率/置信度、限制过期回复；在本地平坦验收世界执行一个六格以内的预定义步行目标并核对实际位置。`decisions.py` 默认只输出建议；菜单 4/5 和 `survival.py` 会实际控制游戏。Laya 在本机小样本测试中有错误选择，暂不允许它通过此入口操控游戏。

## 双击使用

桌面双击 **Minecraft AI 体验.command**：

- **1：Jev 判断**，输入“走到黄色标记”“原地等待”等，显示模型结果；不需要开游戏。
- **2：Laya 判断**，做同样的本机比较，不操作游戏。
- **3：控制测试世界一次**，只使用 Jev。按下面步骤打开游戏后，在菜单输入指令，再切回游戏、关闭暂停菜单并松开移动键。工具会核对实时地面、标记与通道，最多等待 30 秒，只执行一次。

测试世界启动步骤：

1. HMCL → 实例列表 → **26.1.2** → 游戏设置：开启**版本隔离**，快速游玩选**无**。
2. 在该实例页面点左侧 **测试游戏**，进入单人游戏 → **Jev Local Test 20260921**。不要从首页启动原来选中的 `once` 实例。
3. 站在白、蓝或黄色地面标记附近，落到地面，关闭聊天和物品栏。
4. 双击桌面入口，选 **3**；例如输入“走到黄色标记”，然后切回 Minecraft。结束后回工具窗口查看结果。

每次会扫描当前测试场地，并使用当前位置，不需要手动修改旧计划的起点。打开聊天、菜单、有其他任务或推理期间角色移动时会拒绝接管。要中断动作，可用游戏里的 **U → 紧急停止全部**；不要把关闭工具窗口当作即时急停。

测试结束后，如需恢复原来的 26.1.2 使用方式，关闭版本隔离，并把快速游玩改回“多人联机 / simpcraft.com”。标记演示与生存试运行入口均不支持多人服务器；日常 Kit 挖矿/投影建造仍是独立功能。日常挖矿仍使用原来的 Kit 菜单。

这次大模型提供目标和测试方案，Jev 选择候选，Kit 通过正常游戏输入执行。没有自动接通另一个 GPT-6 API，也不是已验证的自主生存/战斗系统。

## 生存开局试运行（实验功能）

再次使用现成验收存档：HMCL → 26.1.2 实例设置 → 开启版本隔离、快速游玩选“无” → 左侧“测试游戏” → 单人游戏 → **Jev Survival Bootstrap 20260921**。

桌面入口新增 **4：基础营地试运行** 和 **5：继续到铁装备**。需要隔离实例中的 Kit **1.9.39** 或更新版。
先进入名称以 `Jev ` 开头的独立存档，保持生存模式、主世界、至少 8 颗心和 4 格饥饿值；关闭菜单和其他自动功能。然后选择 4 或 5，切回游戏。

程序按任务表推进：采集 12 个原木 → 工作台和木镐 → 14 个圆石 → 石镐、石斧、熔炉 → 获取并烹饪食物 → 带门的 5×5 庇护所。
选择 5 还会采集附近裸露铁矿、熔炼 30 个铁锭，制作并穿戴全套铁甲和盾牌，保留铁镐、铁剑，最后回到庇护所。已有装备会按实际状态扣除需求。
Jev 在每次手动开始时识别目标工作流；此后由本地任务表连续推进，寻路、逐块操作、材料计算、合成和结果核对不再重复问模型。当前不是模型自行生成长期计划，未接入下界或通关。

条件与边界：

- 只扫描附近已加载地形，约 16 格；不使用飞行，不进入多人服务器，不读取未加载区块。
- 需要附近有可达原木、裸露石头、土方、牛/猪/羊/鸡和空置的 5×5 平地。当前没有远距离探索、开矿井或复杂高树处理。
- 获取食物会攻击上述被动动物；不会拆除箱子等容器，也保护已规划的庇护所地基。
- 遇到敌对生物、低血量、饥饿、失焦、菜单或人工移动会暂停。这版不是自动战斗防护；建议先在和平测试存档使用。
- 基础营地每次最多 30 分钟，铁装备最多 45 分钟；两者最多 24 次 Jev 请求，正常一次启动只需 1 次；不启动常驻服务。WASD 接管或 **U → 紧急停止全部** 会停止任务，急停后不会自动恢复。
- 进度在 `~/Library/Application Support/MinecraftDecisions/survival/`。再次选择 4 或 5 时，仅在存档和附近位置匹配时读取续跑记录，并重新检查游戏实际状态。合成栏里留下材料时，需要先整理再继续，不会丢弃。

命令行可指定预算或续跑记录：

```sh
"$HOME/Library/Application Support/MinecraftDecisions/venv/bin/python" survival.py \
  --world 'Jev Survival Bootstrap 20260921' --minutes 45 --max-calls 24 --iron
```

验收场地的原木、矿石、土堆和静止动物（NoAI）由独立数据包预先布置；角色从空背包、生存模式开始，运行中的采集/合成/放置只使用正常交互。此场地用于检查技能，不能据此宣称随机种子或普通难度已能自主生存。

## 使用

在本目录运行，计划包含 `goal`、`choices`（含 `wait`）、简短 `scene`。Laya 的输入会先做长度检查，避免静默截掉观察内容。

```sh
PY="$HOME/Library/Application Support/MinecraftDecisions/venv/bin/python"
"$PY" decisions.py --provider jev --plan /完整路径/plan.json
"$PY" decisions.py --provider laya --plan /完整路径/plan.json
"$PY" benchmark.py --provider laya --output /完整路径/laya-results.json
```

只有显式加入 `--execute-local-test` 才会发出动作。计划还需提供 `origin`、候选 `targets`，操作者应先用 Kit 扫描确认测试地面、头部空间和目标标记。入口仅允许 `singleplayer` 主世界、健康玩家、平坦六格内目标；拒绝菜单、已有任务、明显的人工移动、推理期间位置变化、低置信度或超过 1.5 秒的决策。

```sh
"$PY" decisions.py --provider jev --plan /完整路径/plan.json \
  --automation /完整路径/测试实例/config/twob2tkit/automation \
  --execute-local-test --output /完整路径/result.json
```

`--automation` 必须指向当前测试实例。Kit 动作有 5 秒原生期限；动作结束需匹配请求 ID、完成状态和实际位置。已发送但失去确认的动作标为 `unconfirmed`，不盲目重试；另一控制器接管后停止发新指令。

Minecraft 当前状态接口约每秒刷新，动作请求按客户端 tick 处理，因此“模型 14 毫秒”不等于整个游戏闭环 14 毫秒。紧急停止、避险、碰撞与逐帧操作仍应由本地程序处理。

## 投影建造托管（菜单 6，Kit 1.9.45）

1. 从 HMCL 的 **26.1.2 实例**启动游戏，进入目标世界并到投影附近。本次安装位于该实例的隔离目录；若 Simpcraft 先进入大厅，先右键入口 NPC 进入生存世界。
2. 在 Litematica 选中并锁定要建造的投影，只启用这一份，关闭游戏内菜单。
3. 双击桌面 **Minecraft AI 体验.command**，选择 **6：启动/托管选中投影**。新任务会同时启动建造和原生安全看护；已有任务则接管，避免任务先结束、保护还未启用的空档。
4. 正常放置、走位、物品数量核对都由 Kit 执行，不调用模型。缺料或受阻时，Jev 从本地核验后的补给、原木合成木板、续建、复查、重规划和停止报告中选择。
5. WASD 或 Kit 急停撤销本次托管，程序不会自行恢复手动中止的会话。再次选择 6 才是一次新的手动启动。

### 补给与收尾

打开 **U → 仓库记录**，选中自己的仓库，点击 **建造补给** 切换许可。许可限定服务器、维度、坐标；单人世界还绑定存档路径。这个按钮不会立即拿东西。本次房屋附近的已授权仓库已配置。

取料前核对实际箱子和库存，每次最多 8 次整栈转移，以背包容量为限；额外的同栈材料留在背包，不丢弃物品。确认箱内减少和背包增加后才记为成功。背包满时先用已有材料施工；合成也检查输出空间。路线受阻后只有补到所需的新材料，才允许自动续建，避免反复空跑。

单人任务结束后暂停；多人任务结束、程序退出或失联约 15 秒后自动下线。托管中低于 7 颗心也会原生收尾。手动接管撤销该会话的看护。实际暂停/断开确认后才记录成功。

### 额度与经验

设置：`~/Library/Application Support/MinecraftDecisions/build-supervisor/settings.json`。默认 Jev 最多 120 次/小时、连续两次未解决后合并报告。正常进展不问模型。普通候选动作要求模型选择概率至少 0.6、信心至少 0.5，并在发送前重新检查现场；世界、任务、手动输入、材料、碰撞与健康限制仍由 Kit 强制执行。

同一 Kit 版本、同一服务器范围的两个独立成功任务，才能让已验证的恢复步骤绕过模型。本地日志保留实际模型版本、耗时、选择和结果。新问题进入现有技能库和去重的 `handoff-*.json`；目前不自动调用 ChatGPT，也不自行热替换 Java 代码。开发排错仍由 Codex 完成。

### 已有实测与限制

多人服大型投影先运行 `projection_site.py --origin X Y Z --size 宽 高 深 --output 现场.json`。它在受保护的材料会话中只读扫描每格地基及整座建筑空间，拒绝缺少承托、已有方块或邻近容器的位置；退出时要求原生安全下线。服务器领地权限仍须以首格实际放置回包确认。离线修改 Blender 或图纸期间，不要让无托管的角色留在野外。原生 `safe_logout` 可能先连续推进控制版本再断线，客户端现按本次请求 ID 等待真实断线，不重复发送下线请求。

多人服材料会话可通过 `use_item` 消耗一件**已在快捷栏**的指定食物，即使独立防护正因饥饿暂停，也要先检查近敌、血量和手动输入，并核实服务端确认的饥饿值及物品减少。自动制作混凝土可调用 `concrete_batch`，传入已核实的支撑方块坐标与状态、手持粉末 ID、1–4096 的数量；它只锁定一个相邻有水的格子，实际放置、硬化、挖掘与拾取均需回包确认，最后以背包成品增量验收。没有安全支撑、水或可用镐时停止，不会改写用户界面中的持续制作设置。

多人服熔炉与高炉也可在材料会话中打开与核对，但只操作观察到为空的输入／燃料／输出槽。长批烧炼先放入真实原料和燃料，再关闭界面、保持防护心跳，随后重开验证输出并取回剩余燃料。`craft_recipe.py` 对背包 2×2 格要求背包界面真实打开；在工作台 3×3 格中，`pin_chest_planks` 与 `pin_furnace_cobblestone` 会检查完整八格后才固定一种足量材料，防止标签配方只替换部分格子。

普通生成地图 `Jev Natural Build 20260921` 使用 `minecraft:noise` 主世界、生存、普通难度、无指令。已验证采集原木、Jev 选择合成和续建、8 格实际建造。早期完成后无人看护曾导致死亡，该失败已保留，并推动原生安全收尾修复；不据此宣称全流程自主生存或通关。

Simpcraft 已验证真实箱子取料、原木合成实际产出、真实投影放置和自动下线。该阶段原方案匹配 2212/2880 格；重新交接控制后的几轮新增 29 格，末轮 6 格全程满血。缺少的建材和已占用、不匹配的位置保留；没有通过替换材料、拆掉现有方块或创造模式制造完成状态。整栋房屋、任意材料合成、长期挂机与所有服务器兼容性仍不属于已验证结果。

一次合成因服务器回包慢，实际产出后仍被旧确认逻辑报错；已改为最多 80 次检查的有限等待，不重复发送点击，并增加延迟确认回归测试。这项修复尚未在同一服务器再次遇到实际需要合成的场景。

## 按目标数量规划与制作材料

`material_plan.py` 从已安装客户端 JAR 读取普通工作台配方，计算目标成品、中间材料、成批产出的余量和仍需取得的物品。它会先预留已备好的目标成品与指定个人物资，避免把留给建筑的木板再次用去做家具；原木能合成的木板也参与选料。铁锭与铁块等循环转换不会被当成新材料来源。

离线入口只写计划，不启动游戏、不发出控制请求：

```sh
python material_plan.py --jar /path/to/client.jar --audit /path/to/projection-audit.json \
  --stock-ledger /path/to/recorded-supplies.json --output /path/to/material-plan.json
```

也可用 `--inventory /path/to/snapshot.json` 代替 `--stock-ledger`，只分析一个背包快照。仓库估算仅纳入明确选定的永久箱子或木桶；排除搬动过的潜影盒记录及末影箱，拒绝重复来源。历史数量只是备料线索，必须重新开箱核对。

`goal_workflow.manufacture_targets(client, catalog, targets, keep=...)` 接入已有 `MaterialClient` 安全会话和工作台交互。执行前用实时背包重新规划，每步核对原料、成品和离线锁；缺料步骤不执行，也不使用计划里的“待取得数量”冒充库存。返回值中的 `remaining_targets` 是实际未备齐的成品。

当前只执行普通合成。熔炼、切石、混凝土硬化、去皮、实体与旗帜属性仍由对应流程分别处理，不能用材料计划代替房屋最终验收。安全锁激活时仅允许离线规划，不能运行制作流程或自动重连。

## 现场验收和合成互斥

Kit 1.9.54 起的 `projection_audit` 同时报告封闭空气区中的占位方块、装饰实体和旗帜图案。开放过道仍需单独走位验收；客户端没观察到某个实体，也不等于服务器上一定没有它。`projection_completion.py` 把地形清理候选、原地去皮、容器保护、玻璃连接和其他修正分开，生成精确坐标检查表，不直接拆除任何方块。

1.9.56 起材料接口为 `material_protocol=2`。材料会话暂停未接管的投影打印器，并通过 IPN 兼容钩子抑制托管期间的连续合成补料；不改变用户的 IPN 手动设置。兼容钩子未实际运行时拒绝开启材料会话。急停也会关闭未由 Kit 接管的打印模式，避免工作台与打印器同时改动背包。

`approach_block` 为指定工作方块寻找可见、可达的交互面。`mine_block` 可携带同一个 `face`，防止接近侧面后又改瞄中心而被邻格遮挡。`owned_placement_repair.py` 只处理前后观察证明新出现的错误方块，保留状态已变化的玩家工作，并回收掉落物；它不能把任意旧建筑当成可拆除对象。

## 参考项目吸收：后台决策、恢复和运行证据

2026-09-22 对照 `rmalde/minecraft-agent@78b40ed`，把适用于现有 Kit 的三项机制接入实际流程：

- 菜单 6 的 Jev 推理改为后台单请求，主循环继续读取状态和维护看护；世界、任务、控制权、库存或安全状态变化后旧答复作废。已有正常进度、合成/取料的确定性分支仍不调用模型。
- `work_access.approach_faces` 为确认受阻的移动尝试不同交互面，每次核对同一目标，最多六个面；未知结果和未确认的破坏、库存动作不自动重放。地下室清理和自有错误方块修复已使用此入口。

## 从现场补料与收尾

`stored_supplies.recover_stored` 根据自己的入库记录找回所需成品，按实际背包增量核验，避免把一次箱子访问完成误当成补齐材料。`projection_transit.approach_stairwell` 识别连续木楼梯并中转，解决补货局部搜索范围漏掉远侧楼梯的问题。

`projection_wood.finish_beams` 沿设计轴向使用真实支撑面放原木，再用斧头去皮；只把最终方块状态与图纸完全一致计为完成。近距离交互仅对明确未执行的遮挡/距离错误重找站位，不重复未知结果。该路径在 Simpcraft 已成功补齐 5 根木梁，另去皮 1 根已有木梁。

`inventory_exact.take_exact` 可从容器精确取少量材料并退回余量，预留潜影盒回收空位。其逻辑测试已通过，尚待实机验收；当前运行不会自动调用它。
