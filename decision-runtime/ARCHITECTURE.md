# Kit 控制与组件边界

## 分层

| 层 | 目录 | 职责 |
|---|---|---|
| 原生宿主 | `src/client/java/dev/twob2tkit/` | UI、按键、游戏事件、请求校验与生命安全锁 |
| 可热更新引擎 | `runtime/engine/` | 寻路、挖掘、战斗等高频动作；遵守稳定 `runtime/api/` |
| 脚本入口 | `decision-runtime/*.py` | CLI、阶段编排、现有调用路径兼容 |
| 共享组件 | `decision-runtime/kit_runtime/` | 注入式背包事务、诊断日志等跨流程组件 |
| 领域流程 | `stack_recipe.py`、`furnace_batches.py` 等 | 合成、熔炼、采集的状态和数量核对 |
| 任务数据 | 任务输出目录 | 坐标、材料目标、运行清单、回执、恢复检查点 |

任务坐标和阶段配额写入任务数据。可重复使用的操作、判定和恢复进入 Kit。入口层负责组合领域流程；领域流程通过注入的客户端访问游戏。

## 背包事务

`InventorySession(client)` 独立持有客户端，批量合成与熔炼已使用该组件，执行期间不再改写 `craft_grid.k` 或 `craft_recipe.k`。旧入口保留兼容；迁移调用方时同时补充事务回归测试。

- 发送前核对容器 ID、源物品、数量、目标空位和光标。
- 迟到的确认通过读取状态等待；每次点击只发送一次。
- 小量取料选择点击更少的方案，保留完整的源数量、目标数量和光标核对。
- 熔炉燃料可能立即燃烧，其目标槽不采用工作台的静态数量条件；熔炼流程另核对输入与产出的守恒。
- 角色、世界、容器或控制归属变化时结束事务。恢复依据实际物品与回执，不依据循环次数。

## 恢复与防护

原生防护负责怪物、氧气和低血量响应。Jev 不在这些紧急动作的关键路径上。

暂停工作和暂停防御是不同状态。升空受阻时继续已有的近战、射箭和举盾判定；生命低于安全阈值时交给原生紧急撤离。敌人移出视野不能记成击杀。

脚本结束前等待自己尚未完成的有界动作，再处理潜影盒、工作台和出口。遇到人工接管、失联或持续未完成时放弃新的收尾动作，交由原生看护处理。

`assistant-control-hold.json` 记录用户要求的“只离线改进”。它仅限制脚本和助手探测，不更改玩家手动操作。恢复授权与健康安全锁分别核对，时间经过或服务器恢复响应都不会自动解除授权限制。

## Jev

本地程序给出有限且已验证的候选动作。发送前冻结状态、候选和场景；接收时再次核对控制归属、位置、背包和安全状态。

正常任务直接执行本地流程；需要选择策略时调用 Jev。预算、缓存、超时、置信度和失败退避均有界。结果记录来源：`jev`、`cache`、`local`，以及本地回退原因。诊断日志写入失败不会改变已验证的策略选择。

## 日志与诊断

- `events.jsonl` 和阶段回执是实际事务证据，保留原始数量与请求 ID。
- Jev 诊断日志经过脱敏、大小限制和轮换，最多保留当前文件及 3 份备份；不轮换原始事务证据。
- `diagnose.py --run <运行目录>` 只读取有界日志尾部和本地状态，汇总耗时、失败类型及 Jev 来源，不扫描全部历史、不操作游戏。
- 摘要明确标记尾部范围、观测时间和未知值。测试通过、点击成功与工程完成分别记录。
- 原生状态写入失败和超过 250 ms 的状态生成会限频记录，避免静默失效和日志刷屏。

## 交付一致性

`kit_release.py` 在游戏退出后从已构建的主 JAR 提取配套引擎，同时备份和更新外置引擎；验证哈希并在写入失败时回滚，避免新版宿主继续加载旧引擎。安装过程不会启动游戏或连接服务器。

## 熔炼与材料续接

`furnace_bank.py` 负责选址与逐座摆放回执；`furnace_batches.py` 负责每炉原料、燃料和成品守恒；`smelting_workflow.py` 负责核对旧计划、跳过已装料步骤以及有上限的等待。任务坐标和两轮配额留在工程脚本里，不放进共享组件。

- 原料和煤可以分散在多堆；每片用同一个 `InventorySession` 装入本批已确认的输入/燃料槽。工作台仍只允许空格放料，不开放任意同物品追加。
- 已确认的炉位重新读取实际方块后可跳过；所有未建炉位在首个放置前预检，炉间留一格空隙。明确的交互前拒绝可重新寻路，不确定点击保留 `pending`，不能重放。
- `kit_runtime.journal.write_json` 先写临时文件并同步，再整体替换回执，普通写入故障不截断上一个完整记录。
- `material_depots.audit` 必须完成全部指定箱子的读取后才返回完整存量；中途断开、换控制或菜单异常不会把部分数目当作总库存。制造目标扣除新审计的已存成品，箭矢等随身物品仍按背包目标保留。
- 续接同一游戏会话且完整装料的批次时，不重新提取原料。已收取阶段可以直接核对存箱结果。任何阶段部分装料、未知点击结果或换世界会话均需先核对，不能宣称任意断网后自动恢复。
- 每次恢复写入全新的输出目录；熔炼任务的原始目录记录各次运行路径，防止遗漏前一次恢复期间尚未归还的潜影盒。
