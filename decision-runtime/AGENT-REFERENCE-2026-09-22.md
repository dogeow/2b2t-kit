# Minecraft Agent 参考吸收记录

参考仓库：https://github.com/rmalde/minecraft-agent ，读取版本 `78b40ed59514e5e2abde33a05ce398ecb2c39e05`。

原帖页面本次无法直接读取，以下依据仓库代码和作者 README；没有在本机复现它的通关成绩。代码按 Kit 的接口独立实现，没有执行参考仓库的安装、凭据或启动脚本。

## 运行条件和可迁移范围

README 报告的 8 分 43.300 秒使用 Minecraft Java 1.16.5、生存/和平难度、预先调查的固定种子、天然已激活的末地传送门；35 次 Astra 调用、131 次 Jev 决策是作者记录的结果。代码把结构化游戏状态和有限动作提供给模型，再由 Mineflayer 执行。原生客户端主要用于显示和录像，不能据此理解为模型仅看屏幕、从随机种子自行探索通关。

Kit 当前目标是 26.1.2 的真实多人服和既有角色、仓库、投影。保留 Fabric/Meteor 的原生执行器，不引入另一个 Mineflayer 角色；不导入固定路线、种子坐标、旧版网络包编号或演示场地设置。

## 本次落地

1. 参考 `async-planner.mjs` 的后台规划和阶段失效机制，在 `background_decision.py` 实现单请求后台邮箱，接入现有 `build_supervisor.py`。主循环继续读取新状态和维持原生看护。世界、任务、投影、控制权、库存、候选动作变化时丢弃旧结果；人工接管或防护介入也会撤销结果。超过 5 秒的方案不执行，连续超时合并为交接报告。正常进度不调用模型，限额在发出请求时计数。
2. 参考 `optimization/policy.mjs` 和 `navigation.mjs` 对失败、部分进展和有限动作的区别，在 `work_access.py` 将确认的寻路/交互面受阻与未确认动作分开。地下室清理和自有错误放置修复最多尝试六个不同面，每次重新核对目标状态。移动到了附近但射线被挡时换面；目标改变、超时或未知错误仍停止。不会重复未确认的挖掘或背包点击。
3. 参考 `optimization/nether/freeze-run.mjs`、`compare-runs.mjs` 和 `evidence.mjs` 的可复现证据，在材料会话生成独立运行清单，记录 Kit 版本、真实难度、世界范围和关键脚本哈希。动作日志增加请求 ID、耗时、控制版本及前后位置、生命值、背包差量。原生回包确认仅代表该操作，不代表整个房屋或目标完成。凭据、环境变量和完整配置不进入清单。

## 使用和验证边界

桌面 `Minecraft AI 体验.command` 指向本仓库，菜单 6 会使用新的后台监督逻辑；后续新材料会话会写入证据清单。纯 Python 改动不要求重启游戏。

模型异步性用真实线程和受控慢响应验证，没有为测试发送付费模型请求。测试覆盖单请求限制、慢响应期间持续状态检查、人工停止、库存改变、失效结果、换面上限、目标被改动和运行清单字段白名单。多人服的进一步运行结果另记，不把模拟测试记作实机通关。
