# Kit 热更新

从主包 1.9.66 / 运行引擎 1.7.57 开始，投影的 A* 寻路、站位候选、走位减速、到位判定、搜索预算和离站时机通过稳定的 `BuildNavigation` 接口进入运行包。挖矿和独立防护沿用原来的热加载机制。引擎不得导入宿主实现类；实际碰撞、输入、服务器确认和安全锁仍由宿主管理。

后续只修改上述运行实现时，构建 `runtimeEngineJar verifyRuntimeEngineJar`，运行 `hot_update.install_and_reload(client, jar)` 即可。脚本沿用已持有的 MaterialClient 安全租约，通过 `runtime_reload` 本机接口加载，不需要桌面点击、聊天命令或重新登录。不要同时启动第二个游戏控制器。

手动入口：Kit → 设置 → 通用设置 → 检查并加载运行引擎；也可使用本地命令 `/twob2tkit reload`。入口只加载已放进 runtime 目录的本机引擎，不会自动下载代码。

更新会先检查版本、哈希和宿主 API，备份旧文件，并在客户端主线程暂停施工输入。原投影、任务标识和托管租约保持不变；旧寻路对象被丢弃，新引擎重新检查现场后继续。打印器存在未确认放置、容器未关闭、手动输入、生命不足或正在防御时拒绝更新。加载失败保留原内存引擎，脚本恢复磁盘备份；不盲目重试未知结果。

界面注册、按键、Mixin、稳定 API、新依赖以及尚未迁入引擎的功能仍需要完整重启。主包旧版本必须先升级一次；不能通过只替换引擎绕过接口兼容性。

验证包括分帧寻路、两次独立类加载器隔离、共享稳定 API、有限运动提案、旧宿主拒绝、失败回退与不重复投递。实机结果另存工作目录的 hot-update-proof.json，不把测试通过当成已经在游戏生效。

实机验收：2026-09-22，在同一 Java 进程 PID 23756、同一服务器会话和同一施工任务中，从引擎 1.7.56 热加载为 1.7.57。任务续接后完成 8 个方块匹配（2616 → 2624），生命与饥饿均为 20。验收证据保存在当前建造工程 work/projection-completion/phase23/hot-update-proof.json。

主包 1.9.67 进一步把补货/接近方块的分帧寻路与运动提案接入同一引擎。补货操作期间先等本次操作结束再热更新。`release_scope.classify` 将候选包与实际已安装主包逐项比较，忽略纯版本标签；只改引擎时必须走热加载，主包安装脚本会拒绝不必要的换包重启。

主包 1.9.71 加入受托管租约保护的自由下落逐帧刹车，需要完整重启。调用方先验证开阔的 3×3 下降列，并检查 `freefall_protocol`；宿主在目标上方提前重新开启 Meteor Flight。旧主包不暴露该协议，脚本不得用普通 `walk` 的到位判定代替刹车。
